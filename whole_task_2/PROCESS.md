# 当前流程 v3（2026-10-20）：刚体放置合并，与 Step5 一致的落地 oracle

Step1–3 的定义、代码与数据均未改动（Step3 报告绑定的全部源码哈希保持一致）。v3 只改 Step4 的搜索与 oracle、Step5 的安装转角搜索，并加入双臂视频。接受条件、验收代码、75% 合并门槛、几何体积容差 `1e-10 m³` 与受力容差 `2e-9` 均不变。

## 算法（一句话：把一件已验收的支撑刚体地放到另一件上，留下合法且省料的并集）

1. 状态是一组已完整验收的支撑，初始每个 task 一件（Step3 的 13 个薄壳）。
2. 唯一的高阶操作是合并 A+B：对 B 整件施加刚体运动 C，合并件 = (A ∪ C·B) − 所有 task 的工作扇形与原非凸连续退出，按所有安装地面裁切，保留最大连通块。它必须支撑全部 task（每 task 32,768 对原始载荷与连续锥）、全部原始面棱柱连续退出无碰撞、能按 Step5 的方式落地，且 V(AB) ≤ 0.75×(V(A)+V(B))。
3. C 的搜索：Rotational reuse 在 SO(3) 中采样旋转，Juxtaposition 只取单位旋转；用 LP 求平移，使所有压力凸包位于对方所有安装地面之上，并沿随机方向或朝主组材料内部接触；在真实构造上精确评分（失败 task 数、是否满足门槛、体积），局部 (1+λ) 细化（4°、物体尺寸的 5%），最好的几个做完整验收。
4. 种群（32 个 sample）和已验收子组的族库决定合并哪两件。种群结束时若只剩两件，对同一个合并操作投入全部并行算力（终局：240×16 个旋转，3 轮“从已知最好放置细化 → 完整验收”，已验收但超门槛的放置也作为细化起点）。

所有步长与重叠都相对物体尺寸或薄壳厚度给出，宽相网格取支撑三角形的典型尺寸，筛选按次数计，墙钟时间只作保护上限，便于换其他形状。

## 为什么改：v1 的四个算法问题

以 v1 冷启动结果（`data/B/step4_compact_families/`，2 组 9+4，437.847 cm³）逐项复查：

1. **种子过不了地面条件。** 高阶提案只用座位对齐（R）或零旋转（J），再做只允许平移的地面 LP。对最终 9+4，72 个座位对齐种子中 53 个 LP 无解，其余 19 个被裁地切掉主要接触；随机三维相对旋转则有 17.5–38% 地面可行。
2. **排序不认识“只保留最大连通块”。** 采样 guidance 不模拟并集切除后丢弃小块；约 660 次子试验以 “No actual support boundary／No actual contact polygons remain” 失败。
3. **种群按固定轮数停止。** 32 个 sample 用完轮数时最大只试过 9-task 合并，9+4→13 从未被提出。
4. **Step4 的 oracle 与 Step5 的落地模型不一致。** Step4 以每个安装的世界 z=0 为地面、用非凸扫掠构造自由空间；Step5 以薄壳最低点的切平面为地面（唯一自由度是保持座位的绕针轴整件转角），用退出路径凸包构造地脚可用空间。因此 Step4 会接受 Step5 无法落地的组：一个 319.951 cm³ 的 13-task 单件在所有转角下最好只有 −4.4 mm；另一个 9-task 组转角可行，但没有地脚可用空间。v3 的 oracle 直接调用 Step5 同一个转角搜索（`FloorObjective`）和同一个地脚可用空间函数（`ground_oracle.foot_regions`，Step5 的 `constructive_witness` 也改为调用它），转角写入证书，Step5 从这些转角开始。对已知案例它与 Step5 的实际结果完全一致。

## 加速：只算变化的部分

剖析 9-task 合并（单位 s）：

| 环节 | v1 | v3 | 原因 |
|---|---:|---:|---|
| ground oracle 的见证检查 | 62.7 | 7.1 | 见证网格 90,419 次逐棱柱布尔 |
| 验收中的 exit refinement | 17.2 | 2.3 | 45,198 次逐棱柱布尔 |
| 单个放置的筛选构造 | 1.1 | 0.27 | 每次重建 26 个扫掠／扇形实体 |
| 终局筛选（13-task） | >9000，未完成 | 约 1000 | 同上 |

- **逐棱柱连续退出的精确宽相**（`step4/fast_checks.py`，导入 `membrane_search` 时安装，Step3 文件不改）。在退出方向坐标系中每个面棱柱是一根柱子；若支撑所有三角形包围盒都不与它相交，二者边界不相交，棱柱只能整体在内或在外，由一次点包含测试精确判定，只有可能相交的棱柱才做布尔。9-task 支撑上 85–95% 的棱柱被精确排除，各 task 的重叠上界与失败棱柱集合与原全布尔检查逐位一致。
- **exit refinement 只复查失败的 task。** 重切只去材料、退出行程只会变短，已通过的上界仍然有效；最终行写入审计缓存。
- **oracle 继承薄壳的受力证明。** 见证包含已完整验收的薄壳且不进入任何物体，接触只增不减，配对载荷证明直接继承；见证的全部原始面棱柱、物体与工作区干涉仍逐项检查；最终磁盘复验仍对见证做完整受力审计。缓存的长扫掠并集网格本身有数值缺陷（如 W02 的扫掠 genus −453、含 −0.21 cm³ 内腔），所以不能用“与扫掠并集求交”代替逐棱柱检查。
- **筛选构造增量化。** 父件已排除各自的切除区，(A∪B)−Z_A−Z_B=(A−C·Z_B)∪(C·B−Z_A)，Z_A、Z_B 每个提案只并一次；与真实构造的体积差 ≤0.002 cm³，只用于排序，接受仍用原构造。
- **力筛选只对失败的 task 精确复查。** 先用留在主块内的父接触射线判定，失败者再从实际支撑提取接触；切除边界会把父接触多边形切出新顶点，只用保留射线会误判。
- **验收只做一次完整审计**（取消 refine_exits 前的预审，完整审计内部仍先用 32 个外包目标预检）。

### 双臂使用视频

- **装卸臂 Franka Panda**，末端为 60 mm 杆上的真空吸盘：平行夹爪需要两个相对的外露面和手指空间，在包得较多的支撑里常常没有；吸盘只需一个不在工作区的外露表面点和沿法向的空间，对其他形状也更通用。它从台面停放位取支撑装到工位；在两次安装之间转动空支撑，转角太大时把转动拆成 2–6 段、每段放回台面换手；沿保存的退出方向反向插入兔子，加工后沿退出方向取出放回。
- **加工臂 KUKA LBR Med 14 R820**：针轴方向全程固定，只平移，沿工作区最大连通块描一圈边界再填三道；装卸期间停在一个“摆开位”，它从 A1/A2/A4 候选网格中选出，使其与整段装卸中 Panda 各连杆和被搬运兔子的最小距离最大。交接是显式的：Panda 离开后 KUKA 才用 1 秒回到工作位，加工后 KUKA 先撤离 Panda 再取件。Panda 空闲时转到离针头最远的休息位。

## Step1：定义 task

一个 task 是一组待涂色的源三角面，例如 W08。以工作头前端为球心，针长 **100 mm** 为半径，取名义工作方向 **25° 半角**的球扇形；位于其中的完整源三角面全部计入工作区。区域允许重叠，不按法向、可见性或连通性裁剪，也不补内部缺口。

当前使用 Step1.2 计划的前 **13 个 task**，累计覆盖兔子表面积 **96.7878%**。Step1 的参考工作姿态是合法初始候选，后续可以在保持相同工作面位于球扇形内的条件下调整。

## Step3.2：独立退出方向与最终合法性审查

每个 task 独立拥有退出方向 `d_i` 和长度 `L_i`，路径为纯平移：

```text
T_i(t) = Translate(t * L_i * d_i) * T_i(0),  0 <= t <= 1
||d_i|| = 1,  d_i.z >= 0.05
```

方向首先取该 task 的**反工作方向**。开槽后若不能满足载荷，则优先在初始方向附近尝试 **2°、5°、10°** 的小调整，再搜索其它上半球方向。所有 task 独立搜索，不要求方向相同，也不要求刻意不同。退出长度也独立计算，保证整只兔子的终点高于最终支撑至少 **15 mm**；此处不求最短路径。退出前先撤开工作头。

对每个候选方向，用**整只原始非凸兔子**的连续平移扫掠从倒模减材。扫掠由初始实体与所有正向源三角面沿退出位移形成的棱柱构成，覆盖整个连续时间段；不使用整只物体的凸包，也不以几个采样姿态代替连续检查。

审查分两层：

1. **逐 task 候选检查。** 对挖槽后的局部支撑重新提取实际接触，计算并检查当前姿态下的全部力／力矩要求。失败或数值未解决就换这个 task 的退出方向。
2. **最终整体支撑检查。** 在 Step3.1 支撑上合并扣除所有 task 的退出扫掠，清除浮离平板的材料，并对导出后的实际支撑重新检查**全部 task**。若某个 task 失败，只调整失败 task 的方向并重新构建整体；其它 task 保留已选方向，但也必须重新通过整体审查。

最终接受条件包括：

- 每个物体内部与工作禁区保持留空；姿态、工作面和头部等高关系与 Step3.1 一致。
- 每个 task 的整只物体在整个退出路径上都不与支撑相交，终点完全退出。
- 支撑封闭、接地、只有一个材料连通体，且只是从 Step3.1 支撑减材。
- 从最终实体重新提取实际接触，全部原始力／力矩对及连续力锥保守外包目标通过，实际底面也能容纳所有所需压力中心。
- 从磁盘重读已保存网格，独立重建几何、接触及载荷复验。所有检查通过后才发布结果；搜索耗尽或未解决时不发布新的合法结果。

当前载荷设定为：作用点 `q` 位于该 task 工作面，施力方向位于**机器人名义世界工作方向的 25° 锥内**，幅值 `0–0.5 mg`；重力向下。以物体质心 `c` 为参考，支撑需要提供：

```text
F_required = -gravity - P
M_required = -(q - c) × P
```

力和力矩始终配对求解。每个 task 检查 **32,768** 对原始载荷，并用连续方向锥及工作面作用点的保守外包约束补足连续范围。不是只检查单一法向或几个箭头。

接触模型为无摩擦、单侧、无幅值上限的法向反力，平板按刚性安装处理。几何体积容差保持 **1e-10 m³**，受力容差保持 **2e-9**。因此“完全合法”指当前几何与准静态接触模型全部通过；原生抓取、整臂轨迹和材料强度不在此证书内。

## Step4：共享采样与梯度修复

实现入口为 [step4/run.py](step4/run.py)。默认使用 [population_search.py](step4/population_search.py)，从 Step3.2 的 initialization 开始；旧的分阶段角度扫描作为显式指定的历史入口保留。当前解始终保有全部 task 的有效证书，Step1–3 保持不变。

三个 basic operation 是 **Exit redirection、Translation、Pose rotation**；两个高阶 operation 是 **Juxtaposition** 与 **Rotational reuse**。32 条持续保留的完整设计分支，每轮随机分配 16 条尝试 Juxtaposition、16 条尝试 Rotational reuse，再做梯度修复。每条分支相对自己的父状态严格减小体积，另存全局最优；成功次数由几何与承载条件决定。

每条分支从 **Step3.2 的原始 initialization** 开始，初始每个 task 单独成组，不从旧 Step4 热启动。[group_acceptance.py](step4/group_acceptance.py) 均匀随机选两个不同的组，再在各组随机选一个代表 task。配对不使用当前空间距离或相似度评分，也没有距离阈值分组。成功后仅将这两个组替换为它们的并集，失败保持原分组。因此 `ABC + DEF` 的验收对象就是 `ABCDEF`，其余组保持原参数。解析针轴旋转只用于产生已选 pair 的合法旋转提案，不参与选 pair。

- **Juxtaposition**：将一个已有组整体平移到另一组附近，目标偏移按物体尺寸采样，与 Step3 最初排开的距离无关。
- **Rotational reuse**：同时采样绕固定针轴的合法 pose 和整件支撑的三维安装朝向，使两个 task 能共享同一物体座位或邻近的接触层。对已有共享组，先一起旋转组内世界 pose，并反向调整安装变换，保住组内座位关系，再整体放到另一组附近；不只旋转代表 task 而破坏已有共享。安装不限于 yaw 或 90°。
- **梯度修复**：对两个代表 task，以及完整验收发现失败的组员，依次调整退出方向、各自安装底面的两个切向平移坐标及合法 pose 角度；计算有限差分梯度，并沿负梯度方向回溯。指导目标包含整个合并组、其他 task 的工作／退出禁区和全部实际安装底面。必要时仅投影组内位置以恢复压力点约束，底面与其他组参数不变。先降低配对力／力矩的反力锥投影残差和底面缺失，指导载荷覆盖后再降低材料体积。即使高阶种子已经合法，也先尝试一次基础调整，将种子和调整后真实重建的实体按真实体积顺序验收，保留种子回退；不因未经修复的种子暂时增大体积就禁止修复。方法参考 `slides/Co-optimize/helper_func/continuous_support/block_descent.py` 与 `translation/volume_descent.py`。覆盖恢复期间允许临时候选体积增加，提交仍必须严格减材。
- **按组合并验收**：重建共用实体后，仅对新合并组重新求解完整原始配对载荷、连续力锥和原物体连续退出。其他组参数必须完全相同，保留其完整父载荷证明实际用到的反力基底；无需保留全部未使用接触。优先查询这些基底法向对应的原始允许接触面，验证新实际接触锥包含旧基底；不足时回到全部允许面。基底由未修改的原分类器覆盖全部原始载荷和连续方向目标后提取，缓存绑定父状态及文件 SHA256，旧缓存缺失时只在旧父实体上补一次证明。固定的 7 维辅助射线与真实接触射线分开处理；边界组合可用低秩非负基底重建，仍使用原生成元 13 位去重精度。完整退出包围范围内的有向实际边界完全相同时继承旧路径证明；否则直接对新实体检查该 task 的原始面棱柱。避免对两件几乎重合的完整实体相减。若需要清理旧退出通道中的数值残片，先减材，再重新检查受影响组的载荷。工作空间、实际底面和退出终点必须保持。无法证明时拒绝提案，不扩大分组；体积严格下降且整体连通才保存。最终发布前对全部 task 做一次独立磁盘复验。

每个 task 分开保存世界工作 pose `P_i`、材料从世界的安装变换 `M_i` 和退出方向。执行时同一实体 `S` 按 `inverse(M_i)` 安装，物体座位为 `M_i @ P_i`。优化中可以生成新候选实体；每个候选内部，全部 task 都必须使用同一件实体。没有 PSO。

默认参数见 [policy.json](step4/policy.json)：32 条分支，4 个计算进程，最多 32 轮高阶提议，每次最多 1 轮基础梯度修复。各分支异步串行推进，完成者不用等最慢分支；每个逻辑轮次仍提前固定为 16 次两种高阶操作。失败保留分支原状态；全局最优只有下降才更新。搜索轨迹、梯度、尝试配比和验收证据保存在 data 下，不向 output 写任何额外内容。

每个提案使用独立子进程，默认评估预算 900 秒；到期保留该分支已验收的父状态，不影响其他分支。若超时发生在完整验收的原子提交之后，会校验保存状态的哈希和全部证书再恢复结果。接触验收仅筛去不可能被原始物体面 AABB 查询命中的远处支撑三角面，保留其余实际边界的原坐标；连续退出验收使用沿退出方向的完整路径包围盒，只移除路径外的临时障碍物。全部原始正向面棱柱、原载荷与验收容差不变。

默认梯度使用 [sampled_guidance.py](step4/sampled_guidance.py)：从 512 个分散的原始非工作面和当前接触高权重面生成固定面内探针，用原非凸物体的射线交点判断连续平移禁区，不为每次有限差分重建完整 CSG。顶点探针移向面心 5%，避免向外偏移的裸边顶点绕过退出棱柱，从而虚构没有实际接触面积的反力。体积差分共用固定局部范围的 65,536 个 Sobol 点；承载未恢复时只优化力学残差。完整验收发现失败的原始载荷和压力点纳入后续指导，也检查旧受力基底、承压区和已有连接网络上的固定探针。所有采样均为指导近似，不能接受设计；候选最后仍重新构造真实材料，并用全部允许接触面、完整原始载荷、实际底面、连通性和原始连续棱柱验收。原工作面编号不变。旧精确 CSG 指导保留为 `guidance_geometry=exact` 对照。

- [Rotational reuse](operations/rotational_reuse.mp4)：**6 秒**，保留原来的取放、空支撑转动顺序及 288 帧物体／支撑姿态，针头换成 Pose rotation 同一套 **100 mm 钢针、2 mm 针半径、20 mm 半径和 70 mm 长黑色圆柱头**。从第一帧起就是同一件带两个工作窗口的薄壳，全程只做刚体移动，不切削、增料或替换支撑。两次工作时针尖对准物体表面；取物前工具沿针轴退出 100 mm，第二个 task 放好后再回到工作点。工具方向全程固定。新的全部 288 帧工具／物体／支撑交叠检查通过，见 `data/B/operation_videos/merge/tool_validation.json`。

五个演示均为 **720×720、无底板和立柱**。Pose rotation 额外用英文标出工作方向轴，其余四个视频无文字。Rotational reuse 改用两个较大且互不重叠的工作区域 W06 与 W08，整个视频仅引用一份支撑网格，两次使用共享同一个物体座位。支撑转向约 99.1°，第二个 task 的 pose 允许绕固定针轴调整。两种工作姿态的原始完整载荷、原工作面和连续退出证明保留；换针后，两种安装各作整体平移使针尖接触表面，支撑和物体的相对姿态不变。工具先退出后再取放，转动全程物体已取出；新的逐帧交叠检查使用与 Pose rotation 相同的实际工具网格和原容差。Pose rotation 的原 61 个父姿态覆盖 0–90° 并保留其受力记录；当前演示扩展为 121 个 0–180° 几何姿态，仅重放相同物体与薄壳的刚体转动，不把父载荷证明扩展到新增角度。Exit redirection 与 Translation 仍为几何演示，不新增受力或机械臂运动证书。旧的 `support_merge.mp4` 和 `support_turn.mp4` 已删除，生成入口为 `python -m whole_task_2.operations.render_videos`，可用 `--only exit_redirection`、`--only translation`、`--only pose_rotation`、`--only juxtaposition`、`--only rotational_reuse` 分别更新。数值结果和视频核对记录保存在 `data/B/operation_videos/`，两段新视频各自的 `states.json`、`video.json` 和编码抽帧图位于 `exit_redirection/`、`translation/`。
