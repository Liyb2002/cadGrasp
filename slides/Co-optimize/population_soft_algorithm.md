# Step4：动态换座的32候选优化

## 当前采用V8

用户最重要的要求是：**初始化不指定谁Juxtapose，角色由优化决定**。本轮选用V8，V9/V10是另存的未完成小规模探索，未混入本轮结果。入口为[run_population_soft.py](step4.2/run_population_soft.py)，实际全量执行使用[冻结V8源码](data/results/B/data/system_population_soft_all52_20261012_08/frozen_sources.json)。

Step4.1生成32个注册原位候选：所有support pose = object pose，没有Juxtapose身份、历史布局暖启动或混合角色种子。退出方向完全相同时初始化相同，否则只有原算法的小方向扰动。物体任务旋转始终保持。

Step4.2每个候选每轮的流程：

1. **选操作对象。** 按当前布局全部32768原始需求的失败比例抽pose；Oracle还失败时，加入实际冲突证书与gap权重。受力通过但共享地面/连接仍失败的pose也可参与；没有可归属pose的共同连接失败允许随机探索。已完成的成品不再扰动。
2. **一次变异。** 注册owner先离散換座；已有guest等概率走离散或差分。离散包含新增、取消、换host、角色交换、合并当前安装状态，以及25%概率的联合换座。成员与host均在本次操作时选，起点为世界XY质心对齐。联合换座允许跨过单个角色改变会暂时变差的障碍；原floor必要条件确实证明不兼容时，可继续移走证书涉及的注册角色。未知条件不当作不可行证明。差分从另外两个只读候选读取同一个pose的材料坐标位置差，随机顺序决定正负方向。
3. **一次调整。** 使用原方向、translation、close/up、floor LP高度修复，加上整组平移候选；接触位置/法向只指导已经选定角色与host之后的translation。共享系统未完成时允许多pose联动；合并安装状态时携带其当前成员，避免留下旧状态。物体原旋转与地面合法性继续由原检查保证。
4. **真实校验后接受。** raw变异和调整结果都检查完整原始需求，保留物理评分较好的一个，再与父代比较。成品优先；偶数槽位侧重受力，奇数槽位侧重Oracle。未完成父代的离散变异可有10%概率暂时变差，以保留结构探索。没有数量评分项。

`N/3`只是新增/取消的**采样倾向**，不进入损失、排序、接受、构造或PASS条件。32个活动槽位始终不增加；调整内部的临时探测不是新的种群成员。最多8轮，找到完整成品可提前结束，因此报告实际轮数；这轮是可行性搜索，不宣称体积最优。

PASS仍要求原始全需求、normal-ray Oracle共同连接、实际闭合实体及其原验收全部通过。物理依赖来自此前冷启动的冻结源码，未修改载荷、接触法则或容差。所有52组共263个object pose都用相同V8冷启动执行；3组pilot与49组余下集合互不重叠，只有保存结果合并。[全量结果及每组图片](data/results/B/step4_population_soft_all52_20261012_final.md)记录逐组Evaluation、object/support pose、来源与实际失败。

图片直接在`output/B/[set]/step4.2/`：各pose、所选布局、搜索过程、32槽位分支、Evaluation；不用HTML。这轮只运行Step4，既有Step5结果单独保留。

## V1历史对照（停止的部分试验）

下文保留首轮讨论规格及逐版调整记录，**不是当前默认配置**。V1严格冻结受力成功pose，V2开始允许Oracle冲突参与优化；各版本均没有预设Juxtapose身份。

本版本对应2026-10-12讨论后用户授权的全52组重测。保留旧结果，使用新实验。各组仍有32个固定槽位、8轮、随机种子42；不增加种群，不读历史优化布局作为初始化。

Step4.1：32个候选均从原始注册布局开始，support pose = object pose，没有预先指定谁Juxtapose。若原始退出方向完全相同，初始化也相同；否则保留原算法小幅方向扰动。原始输入和任务旋转不变。

Step4.2每个槽位每轮：

1. 根据**当前这个布局**的完整32768个原始需求mask，计算每个pose的失败比例 `w[k] = failed[k]/32768`。先以 `w[k]/sum(w)` 抽一个操作对象。50%、20%、10%、0%对应62.5%、25%、12.5%、0%，成功pose不加epsilon，不主动移动。
2. 被抽中pose仍在原位时先走离散分支，产生第一次Juxtapose；已是Juxtapose时，等概率选择离散或差分分支。先抽pose使全体操作对象始终遵循失败量比例，避免先选分支后在不同子集中归一化改变该比例。
3. 离散分支在当前候选内新增、取消、重选座位或交换角色。新增/重选的参考pose在其余pose中随机选，可将成功pose作为不移动的参考。起点是世界XY质心对齐，保持原生旋转和合法地面高度，不按接触位置匹配座位。角色交换的两方都必须失败；先让旧guest恢复注册，再让新guest接替其原座位；遇到原anchor自身原位不构成Juxtapose时，以恢复后的旧guest为中心起新座位。
4. 差分分支从另外两个槽位读取**同一个pose**在共同材料坐标系的质心，给当前失败guest施加 `0.6*(A-B)` 加原尺度噪声，少量方向扰动。A/B无需更好，正负差分由随机顺序产生；供体只读。
5. 完整校验变异布局，再执行一次小调整。恢复原调整模块的多方向、正负、多步长探测，包括base-opening；只允许调整失败pose，安装状态平移仅允许该状态服务的全部pose都可调整时。零失败pose的placement、方向、host及所在安装状态offset保持不变。
6. 完整校验调整后布局，以原物理指标比较父代。偶数槽位先看失败需求，奇数槽位先看Oracle包围条件，随后看全体受力损失、占用体积等。完整成品优先，并比较成品BBX与材料。若父代尚未完成，离散结构探索以10%概率允许一次暂时变差的真实变异；不保留额外候选。

Juxtapose数量中心为 `N/3`，**只改变离散操作抽样概率**。令 `d = clip(N/3 - 当前Juxtapose数, -3, 3)`：注册owner的新增权重为 `exp(d)`，如可交换则交换权重为2；guest的取消权重为 `exp(-d)`、重选座位权重为1、可交换时权重为2，最后归一化。数量不进入评分、局部调整选择、接受门槛、连接/构造排序或最终结果选择；删除旧2–4／2–4目标的优化作用。

成功pose参数不主动移动，但其它pose改变共享材料可间接改变其下一轮受力结果，因此每次都重新检查全体原始需求；如间接变为失败，下一次可参与抽样。

全pose受力成功但Oracle失败是边界情况。本次默认严格遵守“成功的先不动”：所有权重为零时hold，不做换座/调整，仍继续原连接/构造认证。`--allow-oracle-fallback` 是显式可选实验开关，默认关闭；开启后才允许按Oracle冲突分配操作权重，不与默认结果混用。

每轮对32个槽位记录事件（hold记为0次调整，真实变异最多1次调整），并保留完整需求证据。为保证失败量属于当前布局，变异前后都使用完整校验；完整校验次数可能比旧32槽位版本增加。32个初始化、8轮、原始每pose32768需求、每轮最多3次新连接与2次新构造保持不变。所有验收仍由原接触/受力、normal-ray Oracle及实际实体Builder决定。

执行依赖复制自上次冷启动冻结源码，仅替换此次控制器及接入代码，避免其它并行工作对物理内核造成影响。仅运行Step4；从保存结果更新每组 `output/B/[set]/step4.2/` 的PNG与MD/CSV报告，不运行Step5。

## V2：Oracle也决定哪些pose仍未解决

`population_soft_all52_20261012_02`使用独立冻结控制器；物理模块与V1相同。首先在三个难集合验证，再以相同源码、32槽位、8轮继续其余集合。所有原位初始化，不读历史优化布局。

启用Oracle-aware sampling：当前Oracle失败时，按其实际冲突证书中的pose/other_pose和各pose的正gap分配操作权重。若还有受力失败，`weight = 原需求失败比例 + Oracle失败gap/物体尺度`；若受力全通过，仅按Oracle冲突gap归一化。没有可归属pose的共同连接失败，才允许随机结构探索。受力和已知Oracle条件都没有问题的pose参数仍受保护；完整成品不继续无目的扰动。

失败数量用于抽操作对象；候选评分回到原连续受力损失，随后比较失败数量。偶数槽位先看连续受力损失，奇数槽位先看Oracle；已完成成品优先比较实际BBX及材料。继续保留10%临时变差的离散结构探索。N/3仍只影响新增/取消操作的抽样概率，不能影响接受或最终选择。

每次修订保留源码、完整事件、旧结果及独立批次。以原始全需求、Oracle共同连接、实际实体构造的PASS衡量进展，报告每个失败集合；不根据历史成功布局预设谁应该Juxtapose。

## V3/V4：共同约束与整组换座

V3（`..._03`）在Oracle失败时允许原调整模块联动多个pose，不再把全局floor LP因移动其它受力通过pose而直接过滤掉。先验证一个此前全受力通过、但floor Oracle失败的六pose集合。

V4（`..._04`）继续验证三个难例，恢复旧方法中有用的方向与平移调整范围，保持身份选择在优化中：

- 合并当前安装状态时带上该状态正在服务的task cohort，保留各任务原世界旋转与相对摆放。否则只挪anchor、留下其guest，会使旧安装状态继续存在，Juxtapose数增加也未真正去掉冲突floor状态。cohort来自当前候选，没有预设成员；角色交换也携带incoming的cohort，已恢复的outgoing不再跟随。
- 增加随机的整安装状态合并操作，参考其它当前状态的任务中心，原世界XY质心对齐后再调整。
- 在优化的调整候选中使用旧`close/up`退出方向求解器，按**新拓扑**重新协调方向；不把它用于初始化Juxtapose身份。允许未完成共同系统的联动调整。
- 增加原尺度的平移探测：1/16、1/3、2/3物体尺度，随机XY方向；提供原方向及close方向下的候选，不按历史接触匹配定位。
- 局部调整与所属槽位的偏好保持一致：偶数槽位先改进连续受力损失，奇数槽位先改进Oracle。避免所有局部调整都优先Oracle、覆盖受力较好的变异。

32个活动候选不变，每槽位每轮最多一次结构/差分操作和一次调整；调整内部可有多个临时探测。所有初始pose均为注册原位。N/3仍只控制离散操作倾向，验收与身份完全由优化中的实际全需求、Oracle和构造结果决定。联动调整可能移动受力通过但共同系统仍失败的pose，事件分别记录protected参数与force-successful参数是否保持，避免混淆。

## V5：离散分支可联合改变多个角色

`..._05`继续相同三个难例。25%的离散操作采用joint-reseat：在优化这一刻按N/3中心抽换座数量，包含本次失败量/Oracle加权抽中的owner，再动态抽其它成员。若原注册floor子集被原32768需求的必要条件证书证明不兼容，继续随机移走证书涉及的一个角色，直到必要条件可行或只剩一个注册状态。未知/数值未决条件不能冒充不可行证明。

每个新guest先按世界XY质心重合定位，仍由本次优化决定anchor。一次调整中可联合探测多个guest的XY平移，并按新状态协调close/up方向。身份和数量均未写入Step4.1；每轮每槽位仍只有一个试验候选，N/3只控制抽样，最后必须通过实际完整验收。这个较大的离散跳步用来跨过“只改变一个角色会暂时变差”的结构障碍，不从历史优化结果读取身份或坐标。

## V6–V8：保留旧摆放能力，修复调整接入

V6在优化调整中恢复3D质心高度对齐和旧接触位置/法向相关的translation候选。它们只调整当前已经分配好的座位，不选择初始化身份或按接触匹配挑host。中心XY初始化保留；合法高度和原任务旋转仍由原投影/验证器保证。相同所选布局的重复过程截图跳过，所有32槽位的每轮统计照常保留。

V7恢复旧`repair_height`：结构变异与新增translation候选遇到真实floor冲突时，使用原全需求floor LP提议高度，随后仍用原Oracle和完整受力校验。取得真实完整成品后可提前返回，32槽位不变，8轮作为上限；初始化已完全通过的组可能不需要结构变异。这是可行性搜索，不宣称体积最优。实际轮数、已执行事件数必须按保存记录报告。

V8修复一个接入错误：先完整校验变异的raw布局；一轮调整后也完整校验，**在raw和调整结果中按真实物理评分保留较好者**，不能因为近似screen评分而丢掉已通过原需求的raw。实际受力全通过在对应槽位评分中优先于仍失败的布局，再比较Oracle/连续损失等。事件同时保存raw与最后trial的摘要，便于核查。完成成品仍优先比较真实BBX与材料，N/3不参与评分。

旧的V1在途工作自然结束后留作部分对照；不继续未开始的V1集合。V2/V4/V5/V6/V7不再推进的探索保留冻结源码、已完成结果和部分轨迹，并明确标注停止范围。最新全量验证必须完整覆盖52组，不能把这些部分试验当成全量结果。

## V9：恢复原安装状态内的平移换座

旧方法还有`preserve_state`座位族：guest保留自己的原安装旋转，只平移物体与支撑的相对位置。先前只保留了换到其它host的操作，遗漏了这一族，会改变可用接触和地面反力条件。

V9在离散操作中加入native-slide，联合换座也可随机采用这族。owner仍按当前失败/Oracle抽取，中心仍按当前anchor的世界XY对齐，原旋转和合法高度不变；中心原已相同时，采样一个小XY平移使座位确实改变。接触translation在后续调整中指导位置，不在初始化中指定身份或选择支撑状态。Native状态内的平移同样可能计为Juxtapose，支撑安装数量须按实际世界变换统计，不能用`N-Juxtapose`推算。

## V10：扩大实体校验候选，不改变物理验收

原先仅给点云全通过或未通过需求数≤512的布局做实际实体构造。这是效率筛选，可能挡住空间已有解、但点云近似较差的布局。

V10试验放宽这个候选资格：必须已完整检查当前布局的全部原32768需求、原任务旋转和Oracle包围条件；优先选受力最接近通过的候选，连接/构造仍用原每轮3/2预算。原Builder对点云未通过的实体继续执行既有的实际接触多边形顶点验证，全部原需求必须通过。未过实际受力、连接或实体构造的候选仍是失败，不能因为资格放宽而成为PASS。这里只改变“哪些布局值得做更精确的验证”，不改任何接触/力学/几何容差。
