# B：满足原承载约束，减少支撑材料体积

优先用同一个物体相对摆放，通过转动空支撑容纳不同物体 pose。Direction 无法解决的任务才选择性 Juxtapose，随后调整 Translation 与 Direction。每个任务分别插入、作业和取出，不要求物体同时存在。

**全部原始力／力矩、完整退出和工作面约束是硬条件；真实实体材料体积是优化目标。** 支撑摆放次数不作为代价。实现独立保存在 [pose_set_search](../../../../pose_set_search/)，生产 Co-optimize 代码保持原样。

1–7 从同一路线的已通过检查点继续优化，材料从 119.130 cm³ 降到 109.031 cm³，减少约 8.5%。Direction 试出的 104.209／105.287 cm³ 候选损失原载荷，因此拒绝。最终布局重新完整构造和验收，保存原始边界直接导出，导出体积与验收体积一致；每个 pose 的全部 32,768 条载荷另存非负反力证书，包含第七维不上抬条件。

1–10 的增量路线先保留前六个 pose 的转动复用，加入 pose7 后它的切除伤到旧接触；将这个尚未接纳的 pose7 Juxtapose 到 pose6 后，七个任务一起通过。pose8–10 均可继续转动复用。十个加入前缀全部通过，最终只有 pose7 改变相对摆放。

可行体积下降阶段，整体路线从 125.390 降到 116.210 cm³；增量路线从 136.986 降到 110.171 cm³。该增量结果比该整体结果小约 5.2%，本次应按材料体积选择增量结果。两种顺序都进行了多步候选及全部载荷复核，这不意味着增量顺序对所有集合都更好。

历史 1–10 两份最终 OBJ 的实际材料体积为 285.386／208.951 cm³，新的对应结果分别减少约 59.3%／47.3%。这不是受控版本／预算／速度对比。新路线不使用整组全部 Juxtapose，不强制共同世界 `+z`。每格显示保存的实际支撑摆放和世界退出方向。

构造与体积优化分阶段延续，记录在各报告的来源、候选轨迹和代码快照中；7-pose 和整体 10-pose 继续其既有构造检查点，增量 10-pose 延续已通过的六个原生前缀。最终布局完整再生，图没有沿用旧的网格重导入简化结果。

图使用 Step4.1 的蓝色实体支撑、灰色物体、退出箭头和半透明扫掠画法；每格蓝色均为同一个导出实体在保存的支撑摆放下渲染，没有为显示额外切材料。路径图显示前 100 mm，实际验收覆盖完整 619.1 mm。
