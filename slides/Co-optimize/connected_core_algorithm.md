# Step4 连通接触主体与 Step5 的 BBX 优先删减

用户决定（2026-10-12）：Step4 在原有合法包覆材料内得到一个连通主体；Step5.2 只删材料；Step5.3 继续生成支撑脚。Juxtapose 的身份仍在优化中决定，初始化不指定。

## Step4

1. 沿用原来的包覆厚度、工作空间、退出路径和最终地面限制，生成当前 layout 的实际包覆实体。
2. 提取真实材料连通分量，保留最大分量，删除其余孤块。删除只是一项候选操作，不能据此宣称受力可行。保留真实内腔，不以外表面封闭体替代材料。
3. 原七维反力锥继续联合求解物体平衡与共享支撑不被上提：`sum(head_force_on_workpiece_z) - N = 0, N >= 0`，因此物体对支撑的竖直合力向下或为零。删除孤块后，该条件只使用保留主体的接触，不能由不同独立块互相抵消。另做外载向下的必要预检查：保存的 `need_wrench` 是所需反力，其竖直分量应为正；不改变需求数值或符号约定。
4. 在与 OBJ 导出一致的实际剩余接触多边形上，对每个 pose 的全部 32,768 个原始需求重新检查力、力矩覆盖。孤块的接触不得继续参与覆盖。
5. Oracle 仍判断最终各安装状态的触地承载机会，并保存长脚可用的合法空间。其连接证据必须包含保留的真实接触主体，不再要求包含已删孤块上的接触点。它不能替代主体自身的连通判定。

完整连接检查的失败证据必须保留，后续便宜的触地预览不能把它覆盖为成功并使所有候选 hold。有限包覆实体若有少量材料位于 Oracle 合法域之外，可实际求交删除，提案删除量最多为主体的1%，再保留单个真实材料分量并重新检查全部原始需求。该提案上限不是通过容差；原空间/包含容差仍为 `1e-10 m³`，不能通过放宽阈值接受。实际裁剪会刷新保留接触的指导缓存。Oracle 保存的合法空间使用与支撑相同的 16 位 OBJ 精度。

搜索先以保留主体上的原有接触采样检查全部原始需求，接近可行的候选再使用实际接触多边形完整认证；采样通过不能替代实体证书。已经检查的候选使用保留主体的反力列计算原来的固定／自适应需求距离，未检查的微小梯度探针仍使用便宜的原指导模型。先以 32 个注册初始化的冷启动 sample / 8 轮验证；新增可配置的种群数量，失败时可独立运行 48 个 sample 的实验。新运行不能覆盖既有数字、证书或冻结代码。

难组可启用 `--allow-geometry-validation`：每轮从现有槽位中选最多三个不同布局，直接检查保留主体的真实接触多边形，避免点采样漏掉边缘而被误判失败。仍然先取得主体的完整力学证书，才检查 Oracle 和长脚参考；长脚的额外接触不能补救主体。可选的 `--allow-native-sliding` 沿用已有平移换座提案，保持任务原朝向、在优化中改变座位，不指定初始化角色；实际启用情况写入各次运行参数。

连通模式的初始槽位复制同一套原始注册布局与退出方向，避免为 ±0.125° 的可选初始微扰反复构造实体；保留原微扰的 RNG 抽取次数，变异阶段的随机流仍衔接在相同位置。身份都未指定，候选通过各自的随机操作逐渐分化。

当连通候选仅有 1–512 个原始需求失败时，短调整额外尝试两个失败最多的 pose：退出方向沿两个切向轴转动 ±0.03125° / ±0.125°；对 Juxtapose pose 再尝试各轴 ±物体尺度/2048 或 /512 的平移。这些都是同一次调整中的提案，保留槽位数量仍不变，原始力学、空间和实际接触验收不变。

真实接触已认证、但还有少量需求失败的候选，也尝试将失败且离地的 Juxtapose pose 沿世界 Z 向下平移到其原任务允许的地面。原任务朝向和当前角色保持不变；原有物体触地反力只在实际合法触地后启用，全部原始需求、合法空间和主体连通性仍重新检查。短调整可从跳步前保留的候选提出这一高度修复，避免大跳步丢失接近成功的布局。失败的修复候选不替代原候选。

对本轮新搜索已保存的失败槽位，可另开明确标注的继续精修实验；沿用该次原始注册初始化和搜索轨迹，额外实际接触测量、调整次数及父实验单独记录。它不是另一轮冷启动，也不读取此前接受的历史优化布局。不能把这些额外计算说成相同的八轮计算预算。

正在执行的本轮候选也可从已经写出的过程 NPZ 继续：先把该 NPZ、已完成轮次的完整槽位轨迹、原初始化指标和运行参数复制为只读输入，再独立验收。原搜索继续运行不会改变这份输入。继续控制器也复制为只读输入，原有 32／48 槽位不重新初始化，新增测量和精修次数单独记录。可选精修还使用原来的共同退出旋转及较大的 guest XYZ 平移；任何改动都重新检查全部 pose，不能用改善某一个 pose 替代整组通过。

组件提取的新增材料诊断属于 Oracle 裁剪之前的实体。若该诊断超过原几何容差，最终审计会从原包覆输入和所选布局重建有限材料域，直接测量保存主体在该域之外的材料；最终包含关系仍要求不超过 `1e-10 m³`。不修改已有报告数值，也不以裁剪前的诊断代替最终实体检查。

原有搜索内完整支撑构造继续作为长脚可行性参考和完整 BBX 估计；保存的 `support.obj` 必须是已经连通、实际全需求通过的接触主体，不得借用完整参考实体的额外接触来补救主体失败。

[视频07：删除孤立碎块](seperate_base_support_proof/videos/07_remove_disconnected_fragments.mp4)只展示这一小段操作：`pose1+12+29` 的实际包覆材料有5个连通分量。12秒视频连续环绕两圈，前6秒展示全部材料及碎块间隙，第6至7.5秒让4个孤块原地平滑消失，随后继续环绕留下的一个主体；镜头中心与比例固定。删除材料3.082592cm³；最终画面使用已保存并认证的 `support.obj`。已核对三个pose各32,768个原始需求的完整通过mask及真实接触力／力矩证书，不重新求解受力。[来源、组件体积与展示记录](seperate_base_support_proof/videos/07_remove_disconnected_fragments.json)。该操作属于Step4.2的连通主体筛选，当前没有另设Step4.3。

## Step5.2

从该组保存的连通 `support.obj` 开始。先计算固定布局下所有物体与支撑安装状态的共同 XYZ BBX，优先尝试删除把它扩大到物体 BBX 之外的边缘：分别削去各轴高/低端的 100%、75%、50%、25%、10% 扩展，并按真实 BBX 改善排列。所有安装状态的对应平面共同约束同一实体。

随后沿用有界空间分区尝试其它材料删除。每次接受都必须保持封闭边界、一个材料连通分量以及每个 pose 全部原始需求通过；失败就保留上一次结果。候选必须是当前实体的子集，旧候选不能恢复之前删掉的材料。记录各次删除的 BBX 前后值以及材料变化。

每次提交前先将候选按 16 位 OBJ 精度序列化并读回，检查真实边界的包含关系、合法空间、物体侵入、连通性及原始需求。序列化后失效的候选直接拒绝，不能在多次删除后才发现原检查不再成立。内腔和必要接触保持原检查要求。

不能用搜索内长脚参考实体替代未通过的接触主体。固定布局下，纯删除阶段的 BBX 必须不增加。其后长脚阶段的 BBX 单独报告。

Step5.1 的 `record` 是地面需求报告，不包含 Step4 主体策略。后处理必须从所选 Step4 的 `data/report.json` 读取连通模式，再启用删减导出和长脚前的连通守卫；不能因为地面报告没有同名标记而关闭它。最终结果选择只接受删减主体连通、且确实启用了该守卫的长脚报告。

## Step5.3 与结果

保留当前平面渐缩脚、工作/退出/物体/地面裁剪和最终实际接触与触地包络检查。进入长脚阶段前，主体已经连通；需要的路径搜索只服务支撑脚的连接。最终全部原始需求和一个整体仍必须通过。

针对脚与主体布尔合并后出现的微小非法边界，最多执行四次原合法空间求交与脚路径修复。每次都检查主体保留量、合法空间、物体侵入、连通性、触地承载和全部原始需求；容差不放宽。几何简化若填回已删除的材料或非法内腔，就保留简化前的实体。
