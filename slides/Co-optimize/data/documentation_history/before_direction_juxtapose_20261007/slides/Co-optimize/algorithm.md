# Co-optimize：多次装卸的共享支撑设计

## 当前研究主线

设计同一件刚性支撑，服务多个使用配置。每次操作为：抓取物体 → 沿该配置的路径装入 → 落座执行任务 → 取出物体。需要改变支撑摆放时，先取出物体，再重新摆放空支撑；下一次可以换物体姿态或换物体。任务执行期间支撑静止，物体与支撑不作为锁定组合体共同搬运。

每个使用配置指定支撑摆放、物体标识、物体相对支撑的姿态与位置、装卸方向，以及工作面和力／力矩需求。一个支撑摆放可以对应同一物体的多个姿态，进一步也可以服务不同物体；同一实体支撑又可以有多个摆放姿态。不要求支撑姿态与物体姿态一一对应。当前扩展按分别装入使用建模，同时放置多个物体属于后续问题。

核心冲突是：一个配置需要某处有材料提供接触，另一个配置却需要那里为空以容纳物体、工作区域或装卸路径。共同优化方向、相对布局与共享材料，兼顾各配置的承载和紧凑性。面积是几何与材料量，不是接触反力容量。

## 当前实现与阶段

当前代码处理单个物体的保存 pose set。支撑摆放与任务之间的更一般多对多分配、不同物体共享属于后续扩展，文档定义不表示这些功能已经实现。

| 阶段 | 实现职责 |
|---|---|
| Step3.1 | 注册到共享物体坐标 |
| Step3.2 | 共同非工作面包裹种子 |
| Step3.3 | 原始接地环初始化，接地检查作诊断 |
| Step4.1 | 为每个配置初始化共同或相近的合法退出方向，构造扫掠切除与初始支撑 |
| Step4.2 | 比较方向微调与地面切平面内平移的多步幅候选，重建共享支撑并检验全部原始载荷 |

目录为 `step4.1/` 和 `step4.2/`，均为实际代码目录。抓取／几何锁 Step4 目录已删除。历史输出继续使用 `output/B/<set>/step4/step4.1` 与 `step4/step4.2`，不改写已有结果。

### Step4.1：装卸方向初始化

代码保存的是退出方向 d；同一条直线路径反向装入，即沿 −d 装入、沿 +d 退出。优先求共同合法方向；没有共同方向时，用确定性算法初始化相近合法方向。每个配置都有自己的完整装卸路径，支撑切除所有路径的占据并集。

此阶段是构造初始化，力学和接地诊断不等于完整夹具通过。完整包裹是种子，不要求最终保留所有原始墙面或接触。细节见 [Step4.1](step4.1/README.md)。

### Step4.2：方向、相对平移与材料更新

从保存的 Step4.1 方向和零平移出发，候选工具包括单 pose 或联合 pose 的方向调整、相对平移。第一 pose 固定，平移保持各 pose 原始地面切平面；物体、工作禁区、接触区、原始包裹部分及装卸路径随配置位置同步更新。平移是设计布局的修改，不是使用时在支撑内部滑动，不切除重定位过程中扫过的通道。

对接触释放／新增锁定求局部引导，不在求导过程中重建完整支撑。每种更新尝试七档步幅：4、2、1、1/2、1/4、1/8、1/16。入选候选重新构造真实材料、提取接触并检查所有原始载荷。保护所有已通过的具体载荷，要求真实全局最差反力锥缺口下降；收益接近时优先较小占地。累计预算为平移10mm、方向15°和最大投影占地增长20%。具体求导、接受规则及运行命令见 [Step4.2 算法](step4.2/algorithm.md)。

候选生成仍需改善：它目前把旧接触反力作为免费项，未在生成平移时充分处理旧承载的损失。下一步应共同计算缺失承载的接触获得与现有承载的保留／替代，再进行真实全配置验收。

## 当前结果与验收边界

[新版七组实验](data/experiments/multistep_two_tool_v2_B_20261007/README.md)完成2/7，5/7未通过，没有接受平移，没有调用分离保底。两个成功组均只调整方向。历史含分离保底批次的7/7不能当作小平移搜索成功证据。

原始力／力矩尺度、第七维不上抬条件、非负无界接触反力和保存载荷保持不变；检查完整装卸、1%净空及工作禁区。完整夹具连通、实际安装后整件接地合法性和强度尚未验收，当前结果不能替代这些证据。机器人抓取、夹爪与路径约束保留为后续扩展，不加入当前主线的保持／锁定问题。

## 推进顺序

1. 做好同一物体多配置版本，改进平移获得接触同时保留／替代旧承载的候选生成。
2. 放开支撑摆放与物体姿态的一一对应，让一个支撑摆放服务多个物体姿态。
3. 扩展至不同物体分别使用同一支撑，保留共享材料、装卸、工作面、承载与接地验收。
