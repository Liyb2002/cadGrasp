# 恢复原成功搜索的落座范围，连续梯度负责局部修复

原十组成功版本见 [pose_set_search](../../pose_set_search/README.md) 和[生产版真实网格对照](../output/B/large_pose_sets_comparison.md)。前者十组whole的全部原始载荷在采样接触上通过，并检查完整工作禁区；后者十组完成真实网格检查，但主预算是6/10，另外四组有单独记录的续跑。两者都不是新梯度版本的结果。

用户已停止v5整批搜索。停止前完成三组，均未解决；另外一项终止诊断不是完成的搜索。剩下七组不能算失败，也不再继续该批次。52组旧批次仍保持停止。

## 丢掉的有效步骤

v5只使用质心对齐和host方向，每次最多六个落座，主要修复guest方向。原算法同时尝试原位置、质心对齐、多个重叠偏移，以及原guest路径、guest/host中间路径、host路径。原八posewhole案例中，`pose1 → pose10`的原位置和中间路径，一次落座就使其余七pose全部通过；这项候选在v5中不存在。三轮Direction之后，旧版会继续落座搜索；v5则可能因积分误差持续小幅下降而一直拖延。

旧版用接触可用性和锁定计数快速筛选候选。v5直接给少量候选做完整二维切片，缩小了搜索范围，也把精细计算放在了筛选阶段。

## 新代码

入口是 [optimizer_reuse.py](optimizer_reuse.py)。先保留旧 `run.py`、v5及全部已执行源代码快照，避免重写历史来源；本入口必须显式指定 `--sets`，不会自动恢复52组批次。

1. 全部pose共同参与，最多先做三轮全组Direction/已有Juxtapose的Translation连续更新。
2. 尚未整体满足时，调用 [reuse_search.py](../helper_func/juxtapose/reuse_search.py)。直接复用旧版 `ReuseFirstSearch.juxtapose_proposals` 的重叠落座范围；方向种子和初始偏移属于离散落座分支的初始化，分支内部仍做连续优化。
3. 默认快速筛选96项离散布局。采用原连续需求测度的固定分层小求积及原接触锁定计数，对所有pose累积反力锥距离；筛选不是验收，不重建支撑Boolean。预算轮流分配到guest/host及不同偏移尺度，三种方向种子在访问记录中分别保留。
4. 最多六项进入完整表面指导评价，最多三条分支各做三轮全组Direction/Translation修复。使用整组积分误差比较收益与损失，不只修guest，也不使用最远需求作为梯度目标。接触布局已经整体满足时，另检查采样接触上的全部原始载荷。
5. 可行后最多两轮减材料。连续体积步不能破坏已通过的全部原始载荷采样状态；保留已有可行历史。仍可尝试恢复原注册转动复用。最终必须通过更细需求、真实网格及原32768载荷/pose检查。

细求积的位置节点由原内部点改为工作三角形三个顶点及质心，权重为1/12、1/12、1/12、3/4，是原均匀面积测度的正权重二次精度求积。这样更大的力矩力臂也参与指导；原工作角度、需求、无限反力锥、实际物理容差均不改变。Direction与Translation采用同一修复后的可行差分和回溯实现，没有随机连续操作候选池。有限求积仍不是整个连续需求域的证明。

