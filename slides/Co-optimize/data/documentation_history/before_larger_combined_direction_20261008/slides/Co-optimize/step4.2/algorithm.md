# Step4.2：Direction、Juxtapose 与 Translation

日期：2026-10-07。本文定义新的算法设计；当前数值代码仍为旧的 direction／translation 搜索，尚未实现 Juxtapose。旧实现、预算、运行方式与实验说明保留在 [历史算法文档](../data/documentation_history/before_direction_juxtapose_20261007/slides/Co-optimize/step4.2/algorithm.md)。

从 Step4.1 的共享包裹种子、合法退出方向与当前支撑出发，共同设计一件刚性支撑，服务多个分别装入、执行任务和取出的配置。支撑换摆放前先取出物体。一个支撑摆放可以服务多个物体 pose；同一支撑也可以换摆放服务其他 pose。当前先研究单物体，多物体分别使用是后续扩展。

## 三个 operations 的分工

| Operation | 改什么 | 要回答的问题 |
|---|---|---|
| **Direction** | 保持当前相对布局，微调单个或联合 pose 的退出方向 | 改变哪些退出切除，能够恢复有用接触，同时少损失其他接触？ |
| **Juxtapose** | 为当前停滞的 pose 选择另一个 pose 的支撑摆放，直接提出重叠的最终相对布局并补材料 | 利用已有支撑后，还缺哪些接触？材料在哪里加、怎样连接、加多少？ |
| **Translation** | 在当前或 Juxtapose 后的布局上调整相对位置 | 哪里重叠更好？怎样分开接触／空域冲突，同时控制旧支撑损失与占地？ |

Juxtapose 是较大的重叠布局与材料提案，用来处理难以仅靠方向微调解决的 pose，可能增加材料和占地。Translation 恢复为独立的局部工具：Juxtapose 放在哪里仍然需要微调，后续可以继续改变位置和退出方向。新增体积并不自动代表新增承载能力。

## 1. Direction：当前布局上改善退出方向

沿用 [Direction 数学说明](../operation_demo/direction/README.md) 中最不满足的力／力矩需求与反力锥距离。原始尺度、第七维不上抬条件、原始载荷和非负无界接触反力保持不变。

从最差需求识别能补足反力／力矩的接触，计算方向变化对接触释放和新增锁定的影响，提出不同角步幅的候选。某块接触只有不再被任何配置的物体、工作区或退出路径占据时才可恢复。多个相近方向共同阻挡时，可联合调整相关方向。

求导与初筛使用接触几何；入选候选才构造真实支撑、提取实际接触并检验所有配置。方向改动后也要计算旧接触的损失。几何平台或零梯度表示当前局部操作没有进展，不证明该 pose 无解。

## 2. Juxtapose：用重叠布局决定怎么加材料

“死的 pose”指在当前布局与候选预算下，Direction 无法继续改善的任务。选择另一个已有 pose 作为 host，尝试让这个任务也使用 host 的支撑摆放。

### 直接提出最终布局

1. 保持待处理任务规定的世界朝向、工作面与力／力矩需求。选择 host 的支撑摆放，再把待处理物体表达在该支撑坐标中；两个物体在支撑坐标中的朝向可以不同。
2. 利用 host 的现有接触、局部包裹和可用空间提出若干重叠布局。相对位置由几何对齐、占据冲突和所需接触确定，不先指定任意微小位移反复试走，也不把各 pose 远距离分离作为这种 operation 的目标。
3. 优先尝试 host 的世界绝对退出方向，检查该任务是否合法；必要时再用 Direction 调整。共同绝对方向只是复用线索，不是无碰撞或承载保证。

Juxtapose 修改的是设计中的最终配置。无需在支撑中为旧位置到新位置打通平移轨迹；实际装入与退出仍按新配置的完整路径验收。旧配置被新配置替换，不能同时把已废弃的旧物体位置和旧退出通道保留为要求。旧通道中不再被其他配置占据的区域可以恢复材料。

### 在重叠后决定加在哪里、加多少

在最终布局上，沿用 Step3.2 的贴合包裹规则，为新 pose 的所有非工作面生成同样的有限厚度包裹。将它与原支撑取并集，再统一减去所有当前配置的物体占据、完整退出 sweep 和工作禁区。这样保留新包裹中所有不冲突的部分，同时删掉旧支撑里被新配置占据的材料。

贴合几何构造后，再提取所有实际接触，借用 baseline-algo 的联合反力评价检查全部原始载荷，衡量该重叠布局的承载收益。Direction 可进一步改善退出切除。材料减少和承载接触选择可留到后续优化；本 operation 的新增候选先覆盖全部可用贴合区域，不预选少量支撑柱或接触头。

这一版材料量由同样的包裹厚度、重叠布局和全部 sweep 切除共同决定。比较不同 host、重叠位置和退出方向时，同时比较需要加和删的真实体积。几何只围绕最终物体姿态生成；不沿重定位轨迹造滑动通道，不包裹 sweep 本身，也不宣称一步得到全局最少材料。

每个候选必须分别记录：

- 新增及恢复的接触与材料，新增材料如何接入原支撑。
- 新物体占据、工作区和退出路径要求删除的旧材料，以及因此失去的接触。
- 实际新增体积、删除体积、占地变化，以及全部配置的载荷通过情况和最差缺口。

仅看净体积不够：新增与删除可能抵消，却恰好删掉另一个 pose 的关键承载墙。详细定义见 [Juxtapose operation](../operation_demo/juxtapose/README.md)。

## 搜索与选择

Translation 只改当前物体相对支撑的位置，保持任务朝向、原始载荷、工作区域及地面条件。引导可用最差反力／力矩需求的接触几何变化，候选尝试多个平移步幅；更新全部配置的新增、释放和损失接触，再做真实全载荷检验。不把设计横移轨迹切成使用中的滑动通道。

先比较局部 Direction 与 Translation；遇到停滞任务后，采样不同 host、重叠位置和退出方向，以全部不冲突的贴合包裹产生 Juxtapose 候选。入选布局继续用 Translation 与 Direction 改善，两个局部工具都尝试不同步幅。Juxtapose 的位移由目标布局决定，不沿用旧微平移搜索的 10 mm 累计限制作为其定义。

三种 operation 使用同一真实验收：更新所有配置的物体占据、工作区、完整装卸路径和接触；重新构造共享支撑，检验全部原始载荷、不上抬、名义碰撞和接触核心外 1% 净空。保护已经通过的具体载荷，比较真实最差缺口及通过情况；改善接近时优先少加材料、少删关键支撑且占地较小的候选。代理改善或新增蓝色体积本身不能作为接受依据。

最终有限厚度、材料连通、各支撑摆放下的整件接地合法性仍需单独验收；当前无界反力模型不能提供强度结论。新搜索尚未实现，候选排序与预算将在实现时确定，不把旧数值默认值当作新方法已验证的参数。

## 与 baseline-algo／Co-optimize 的融合

Co-optimize 提供共同包裹、合法方向及相近方向初始化；baseline-algo 提供“哪些接触有用、加入后哪些载荷改善”的评价与材料构造思路。Direction 协调当前配置的材料切除，Juxtapose 用已有支撑作为 host，把停滞任务并入并决定还要补哪些材料。保留两者有用部分，不继承固定候选数、支撑头数或头面积作为新方法的硬约束。

当前 Co-optimize 的共同方向在注册后的物体坐标中比较，变换回世界后未必是共同绝对方向；这是支撑换摆放复用的初始化线索。Juxtapose 则尝试增加一个固定支撑摆放下的任务复用。合法方向与完整包裹初始化均不保证全部力／力矩需求可满足。

## 当前实现与证据

当前 `MultiStepSamplingSearch`、批量入口 `run_placement_sampling.py --search multi-step` 仍运行旧 direction／translation 方法；单组 `solver.py` 默认历史 `contact-recovery`。本次仅更新 Markdown，未更改这些数值入口。

[旧多步幅七组实验](../data/experiments/multistep_two_tool_v2_B_20261007/README.md)为 **2/7 通过、5/7 未通过，没有接受平移**；两个成功组均只改方向。这些结果说明旧平移候选不足，不是 Juxtapose 的实验结果。更早的 7/7 含五组大距离分离保底，也不能作为 Juxtapose 或紧凑重叠成功证据。
