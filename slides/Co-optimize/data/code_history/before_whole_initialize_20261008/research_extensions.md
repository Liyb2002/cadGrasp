# 共享支撑设计的扩展思路

日期：2026-10-07。本文记录讨论中的研究方向，不代表已实施的算法、已完成实验或论文贡献结论。当前研究定义见 [algorithm.md](algorithm.md) 和 [Step4.2 说明](step4.2/algorithm.md)；新 Direction＋Juxtapose 尚未整体实现，现有代码仍为旧 direction／translation 搜索。

## 当前推进顺序

主线是多次装卸，每个使用配置有自己的装卸方向与承载条件，空支撑可以换摆放。先实现同一物体的 Direction＋Juxtapose：当前布局上改退出方向，或为停滞任务直接提出重叠布局并补材料。微小 translation 不再是独立 operation。再研究一般多对多配置，最后扩展到不同物体分别使用同一支撑。支撑摆放与物体姿态不强制一一对应；同时装多个物体暂不进入第一版。

固定抓取、薄支撑、几何锁和共同搬运的试验作为历史探索保留，相关 Step4 目录已删除。机器人 kinematics、强度及误差均作为可选后续扩展。下面记录是候选工具与历史讨论，不改变当前推进顺序或已有实验结果。

## 出发点

目前共同／相近退出方向初始化已能解决很多 pose set；讨论中报告约 23/30 组成功，且不少剩余问题可能通过连接材料解决。这一数字仅作为讨论背景，正式论文须明确对应输入、算法版本，以及“成功”是否包括连接、接地、强度和机器人操作。

担心的是：当前方法优雅简单，但技术贡献可能不足。扩展应引入真实的设计冲突，让现有方向协调不再足够，而不是为增加步骤而增加步骤。当前研究本来就在追求共享、紧凑的支撑；不把“紧凑共享支撑”重新包装成一个全新问题，也不把当前紧凑结果称为已证明的全局最小支撑。

## 1. 加工力方向锥从半角 30° 扩大到 60°

已检查 objects/ 中 630 个 pose 的 needs.json：保存载荷锥半角为 30°。方向围绕工作面的向内法向变化，不是围绕世界竖直方向。当前加工力大小在 0 到 0.5mg；半角 60° 对应总张角 120°。

更宽的载荷锥允许更多侧向力和不同力矩，可能使原先可删除的接触变成必要接触。宽锥包含窄锥的连续方向域，但重新抽样的两个有限样本集不自动具有包含关系。对照实验宜保留原 30° 载荷，再追加更大角度载荷；沿用工具可达／自遮挡条件，不把不可执行的加工方向直接计作任务。

关键困难不只是优化方向更难：现有支撑材料可能根本无法提供需要的反力，任何 direction_choice 或 gradient_descent 都救不回来。因此需要新增材料或改变放置。先区分“有限支撑不足”和“在无固定连接的力学模型下任务本来无法平衡”，避免将整体上抬等问题误判成扩大接地面积就能解决。

待检验：原成功组会失去哪类载荷覆盖？缺的是物体接触、接地范围、材料连接，还是任务本身不满足被动支撑条件？60° 仅作为讨论中的扩展，尚未修改数据或重跑。

## 2. 各 pose 的平移与支撑扩展（历史讨论）

以下保留旧微平移建模背景。最新独立 operation 已改为 [Juxtapose](operation_demo/juxtapose/README.md)：以另一个 pose 的支撑摆放为 host，直接确定重叠终点，再共同评价补材料和删旧墙。下面的平移变量与两类工具讨论不是当前操作定义。

当前主要操作是调整退出方向：改变切掉哪些材料，或者恢复原支撑中不再需要切除的材料。这不能创造原始材料范围之外的新支撑。

“可优化放置”具体指物体相对同一件共享支撑的放置可变。第一阶段可保持每个 pose 的朝向固定，只加入允许的平移 t_i，同时选择退出方向 d_i，并重新构造支撑。若仍要求物体接地，平移自由度须尊重该接地条件；不能把任意悬空平移默认为允许。

平移不会自动扩大支撑面积；把物体和支撑一起平移也不会改变两者的力学关系。真正有用的是物体相对共享支撑移动，改变接触位置、载荷相对支撑的力臂、接地需求和跨 pose 材料冲突，并允许相应增加材料。纯粹整体平移一个独立设计在均匀地面上也不改善其内在承载能力。

拟考虑的两类操作：

- 方向调整：改变退出切除与材料恢复。
- 放置调整和材料扩展：引入新的接触／接地空间，使原始支撑之外的材料可参与设计。

搜索变量由仅有 {d_i} 扩展为至少 {t_i, d_i} 与共享支撑几何。可先研究地面内平移，再决定是否放开其他自由度。不同 pose 之间共享多少材料、退出是否冲突，以及是否有足够接地范围，将共同影响放置。

## 3. base 留到最后

用户倾向于将 Step3.3 地面环延后：前面的放置和材料范围还可能变化，过早固定 base 会限制设计。

目前已完成的是展示调整：B 30 个选组的 150 张 Step4.1 图片去掉 Step3.3 接地环，以 Step3.2 包裹支撑为显示范围。算法、保存方向和受力结果未改；历史数值仍对应原有含 base 模型。见 [图片索引](output/B/README.md)。

正式“base 最后生成”的算法尚未实施。需要区分延后构造具体 base 几何与忽略接地力学：前者可行，后者可能让上游得到无法落地实现的设计。可研究用接地需求／可实现性约束指导上游，最后生成实际 base；这只是候选方案。

## 4. 不同物体共享同一件支撑

从同一物体的多 pose 扩展到不同物体、多任务共享一件刚性支撑。不同物体具有不同表面、接触法向、重心、尺度、工作区域和抓取方式；不能直接假设它们已有同一物体注册坐标。

需要联合决定各物体的放置和退出方向，再设计共享／专用材料。为物体 A 提供接触的区域可能挡住 B；提高接触共享的放置可能降低退出和抓取可行性。

避免将问题简化成多个独立支撑远离摆放后用杆连接。紧凑性／材料目标沿用当前研究目标；可通过明确的装置空间或材料预算表达，不能仅以“最终连成一件”证明共享有效。

## 5. Kinematics-aware support design

术语：kinematics（运动学）。建议把方向称为“考虑机器人运动学的支撑设计”。完整操作还涉及抓取、碰撞与路径可行性，不能仅用运动学可达性代替这些检查。

| 讨论中的限制 | 对应概念 | 与支撑设计的关系 |
| --- | --- | --- |
| 哪儿能抓 | 抓取可行性、夹爪开口、接触稳定性、接近空间 | 支撑不能占掉唯一可抓区域 |
| 能否到达位置和朝向 | 逆运动学可达性与关节限位 | 合法退出方向不一定有可执行的机械臂姿态 |
| 哪儿能碰／不能碰 | 碰撞约束与允许接触定义 | 必须检查夹爪及整条手臂，不只检查物体 |
| 手臂弯折太厉害 | 关节限位余量与姿态偏好 | 过度弯折不等同于奇异性，须明确评价指标 |
| 接近伸直等退化姿态 | 奇异性、可操作度 | 有逆运动学解也可能缺少运动余量 |
| 终点能到但过程中到不了 | 连续路径可行性 | 每个 pose 单独可达不保证任务切换可执行 |

术语参考：[MoveIt 运动规划](https://moveit.picknik.ai/main/doc/concepts/motion_planning.html)、[运动学](https://moveit.picknik.ai/main/doc/concepts/kinematics.html)。

核心新冲突：某块材料适合承载，却占据夹爪或手臂必须经过的空间。删掉材料会失去承载；保留材料会无法操作。应让这些约束参与支撑生成与调整，而不是设计结束后接一个机器人检查器。

第一阶段可以固定机械臂型号、安装位置和夹爪，联合选择抓取位置、物体放置、退出方向及支撑形状。固定抓取候选可作为简化版本。是否允许换抓、搬动支撑，以及加工工具是否也由同一机械臂执行，需要在任务定义中明确，不默认放开全部变量。

更完整的目标是实现任务切换：抓取 pose A 的物体 → 退出支撑 → 转动／搬运 → 进入 pose B → 落座 → 松开 → 夹爪撤离。物体无碰撞 sweep 不代表携带物体的机器人无碰撞；放得进去也不保证松手后夹爪能撤出。

技术贡献候选在于设计与操作的共同求解，以及失败如何反馈为材料、放置或抓取修改。仅调用现成运动规划器作末端验证，本身不足以说明新增了设计方法。

## 6. 结构刚度、材料分配和误差

反力平衡通过且材料连通，不代表实际刚度或强度足够。加入加工变形／刚度要求后，连接位置和截面需要与材料共享、退出空隙及机器人通道一起设计；不再是“连上就成功”。刚度与强度指标需要明确的材料和载荷单位，不能只从无上限反力模型推导。

另一个方向是放置误差、物体尺寸／形状公差和间隙。名义模型刚好接触、刚好退出的设计可能对误差敏感。承载接触的可靠性与退出净空之间存在取舍；现有 1% 净空不自动等于完整鲁棒性保证。

## 其他候选研究顺序（历史讨论，未开始实施）

1. 用扩大载荷锥的对照，识别当前支撑和仅调整方向的能力边界。
2. 加入各 pose 的允许平移及材料扩展，研究 base 延后构造时如何保留接地可实现性。
3. 加入固定机械臂／夹爪的 kinematics 与完整操作可行性，使机器人通道参与设计。
4. 再评估跨物体共享、刚度和误差扩展，避免一次放开所有变量而无法识别方法贡献。

优先问题不是让求解器看起来复杂，而是明确当前简单方法无法同时满足的真实需求，并给出可解释、可验证的共同设计方法。以上方向尚无新算法效果、全局最优或论文录用保证。
