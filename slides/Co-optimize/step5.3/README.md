# 历史 Step5.3：固定 BBX 优先的确定性生长

本目录不参与当前流程。新版在 [Step5.2](../step5.2/README.md) 完成实际实体，再进入独立的 [Evaluation](../evaluation/README.md)。以下是加入动态base Oracle前的旧构造与失败记录。

输入是 Step4 当前最终支撑 $\mathcal S_4$、固定支撑摆放 $T_i$、物体位置，以及 Step5.1 的最小需求凸包 $H_i$。先执行 [Step5.2](../step5.2/README.md) 得到固定占用盒 $B_0$。整个算法不调整原 pose、不重新采样、不重新计算 Step4 反力，也不修改原材料文件。

## 目标与真实复用

逐 pose 找现有支撑真正接地的区域 $C_i(\mathcal S_4)$。悬空部分的 XY 投影不能冒充接地。工件自身着地时，它的实际接地点 $O_i$ 也属于系统地面反力；airborne 时 $O_i$ 为空。需要满足

\[
H_i\subseteq\operatorname{conv}\left(C_i(\mathcal S_4\cup A)\cup O_i\right).
\]

现有区域已覆盖的需求直接保留，不增加地脚，也不重新造一圈同样的框。只补当前凸包尚未包住的部分。新增分支可连接旧支撑表面，也可连接已长出的分支；它们在其他 pose 下形成的接地贡献一起更新。

## 先做确定性可行性检查

一件刚性支撑必须在所有摆放下都位于地面之上。公共支撑坐标中的地面半空间为

\[
\ell_j(x)=(T_jx)_z\ge0.
\]

对任务 $i$ 的世界地面点 $p=(p_x,p_y,0)$，其公共坐标是 $x=T_i^{-1}p$。任何合法支撑地脚都必须满足

\[
\ell_{ij}(p)=\left(T_jT_i^{-1}p\right)_z\ge0.
\]

工件只出现在它自己的任务中，所以它的地面接点不用满足其他摆放的半空间。包含这个贡献后，任何可实现的系统压力中心都满足

\[
\ell_{ij}(p)\ge m_{ij},\qquad
m_{ij}=\min\!\left(0,\min_{o\in O_i}\ell_{ij}(o)\right).
\]

$O_i$ 为空时取 $m_{ij}=0$。若需求凸包任意顶点违反这条线性不等式，则固定布局下根本不存在能包住需求的合法 base。这个结论不依赖 BBX 大小、地脚数量、厚度、连接方式或候选采样；增大盒子也不能解决。报告保留具体两项任务、凸包顶点、线性系数及分离间距。

另外检查输入名义网格是否穿过任何地面。只有增加材料的算法不能消除已有穿地；它也不能把这个网格当成已经合法的接地结构。这些检查属于后续 base 几何问题，不改变已有 Step4 搜索接触下的 PASS。

## 可以生长时的确定性步骤

1. 用当前实体接地点和工件接地点初始化各 pose 的接地凸包；已覆盖的凸包顶点不生成地脚。
2. 为未覆盖顶点生成小矩形地脚候选。默认地脚和分支名义宽度 5 mm，地脚底面在自己的真实地面上；不先造完整外围框，不填满需求凸包。
3. 每个候选先尝试连接现有支撑的最近表面／近邻顶点，也尝试已经生长出的材料。直连不能通过时尝试六种轴向折线。
4. 用**完整新增实体**检查所有 state 的地面、全部物体、完整工作锥和退出空间。工作锥、退出空间只在整个候选区域以外封口，不缩短物理排除范围。保留现有支撑内的材料不重新判成新增碰撞。
5. 对合法候选逐项排序：固定 BBX 的实际扩大量 → 所有 pose 新覆盖的需求顶点数（越多越先）→ 新增实际材料体积 → 分支长度 → 固定几何字典序。因此在当前候选中，盒内生长优先；能同时服务多个 pose 的接地贡献优先。
6. 只接受一个候选，更新所有 pose 的接地凸包，再继续补缺口。已有离散片段用同样的完整实体规则连接。
7. 从末尾尝试删除冗余新增分支，要求所有 pose 的覆盖和整体连通仍成立。原支撑材料始终保留；最后记录真实 BBX 增量、实际新增材料和完整动作顺序。

这个算法确定、无梯度、无随机数。矩形地脚、有限附件位置和折线构成一个明确的有限几何搜索，不宣称全局最小材料或全局最小 BBX。候选耗尽单独记为搜索耗尽，不能冒充几何不可能证明。接地凸包覆盖是几何阶段目标；完整地面摩擦／yaw 平衡和强度尚未在这里求解。

## 图与运行

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 .venv/bin/python \
  slides/Co-optimize/step5.3/run.py B
```

每组输出 `step5/step5.3/construction_process.png`、`data/report.json` 和页面。合法生长时图中显示原支撑、部分生长和最终结构，并导出 `support_with_base.obj`。有固定布局矛盾时显示原支撑和冲突图，不导出虚假的成功底座。

冲突图中，橄榄色是 BBX 内对所有地面都合法的最大地脚区域，蓝色是物体自身的接地范围，浅黄色是两者可能提供的系统压力中心范围，红色是原需求凸包；深色直线是分离边界，红叉是违反边界的需求顶点。这里的地脚区域故意忽略了物体、工作和退出禁区，是一个更宽松的上界；连这个上界也覆盖不了时，详细连接生长无法修复它。

总图集为 `output/B/step5.3_index.html`。执行源码、输入指纹和逐组判据保存于本次 batch。算法实现：[growth.py](growth.py)；新增实体访问检查：[access.py](access.py)。

## 当前七组结果

七组固定布局都存在上述线性分离证据，因此输出具体冲突图，未进入材料生长，也未导出成功底座。这里没有重新判断或撤销 Step4 的承载 PASS：它暴露的是在固定摆放下设计共享接地结构的问题。后续若要得到实体底座，需要调整支撑相对地面的摆放等输入约束。

例如第一组的 `pose_27` 要求压力中心位于 $(1.777,-64.946)$ mm。`pose_5` 的地面给出

\[
0.02533144p_x+0.55950911p_y-0.00404845\ge0
\]

（$p_x,p_y$ 用米），自身工件的接地点也无法放宽这条界。需求顶点代入后是 $-0.04034150$ m：低于可达下界 40.34 mm，单位取另一摆放的 Z 高度尺度。增加盒子或多加地脚不能改变这条不等式。

八项几何检查覆盖现有接地复用、盒内生长、单件连通、工件接地贡献、精确分离判据、候选耗尽和重复执行的确定性。真实批次另保存输入及执行源码指纹；不重跑原反力求解。
