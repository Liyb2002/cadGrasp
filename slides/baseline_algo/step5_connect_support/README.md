# Step5：先找方向，再造宽松框架和底座

当前入口 `belt_assembly.py` 调用 `direction_first.py`，schema 为 `direction_first_loose_frame_v1`。Step3 选出精确接触头并保证共同退出方向非空；Step4 仅保存地面需求散点。所有实体、需求凸包和共同轨迹属于 Step5。

## 构造顺序

1. 直接读取 Step3 实际优化后接触头的共同剩余方向 ID，按工作面背向偏好排序；工作面侧与向下方向已在 Step2 排除。装入沿退出路径反向进行，物体固定。
2. 不增加连接，先检查所有原头沿同一方向的完整退出扫掠。未找到方向和完整头扫掠失败分开记录，不删除或重选头，也不宣称任何刚体路径都不存在。
3. 从原头各几何单元的内部引出颈部，延伸到物体背侧的连接平面；同一个已选接触块的所有颈部汇入一个后侧接头，接头数量不随网格三角面数量增长。宽松框架连接所有背侧接头，允许开放树形，不要求闭环或贴着物体表面。
4. 在 Step5 构造需求凸包，并根据退出方向的障碍投影设计开口圈；有限菜单另含较宽的 U 形底座。重新用实际接地材料加工件原接地点验证需求覆盖。
5. 在框架与底座之间选短的粗连接，最终并为单个实体，重验完整装入轨迹、接触保留和共享承载，再生成视频。

## 间隙与连接尺寸

以物体最大尺度 D 为长度基准。框架宽度为 5% D；框架、底座及连接杆对物体预留 2% D 间隙。颈部从原头内部的 85% 缩放实体引出，其较小间隙为 `min(0.01 × 头深度, 0.0001 D)`；颈部是精确头到宽松框架的过渡，不宣称这里也有 2% D 间隙。

连接杆主段宽 4.8% D，底座接头宽 3.2% D，底座宽 5% D、高 4% D。接触面不作间隙偏移。每段材料对物体的间隙由保守立方体膨胀后完整扫掠检查；地面检查使用实际材料，允许底座接地。

这些是几何设计参数；未验证打印强度、柔顺接触或机器人定位误差。整体为一个刚体，路径仅搜索直线平移。有限候选失败不证明所有轨迹都不可能。

## 验证和输出

所有文件位于 `output/{object_name}/{pose}/step5_connect_support/`。不建立独立实验、汇总或视频目录。

- `heads.npz`：保留的原始头实体。
- `direction_search.json`：Step3 来源、剩余和本次尝试的方向 ID、未尝试数量及实际向量。
- `belt.npz`：已连通的宽松框架与头；不代表底座或整件成功。
- `connection.json`、`connection.png`、`audit.json`：完整结果和验证，区分方向、头扫掠、框架、底座、轨迹及承载。
- `geometry.npz`、`support.stl`、`support_mm.stl`：整件几何；两个 STL 分别使用米和毫米。
- `trajectory.json`：成功直线轨迹或明确失败诊断。
- `insertion.mp4`、`insertion.gif`：只在整件连续轨迹通过后生成，仅保留完整轨迹的单视图，不绘制文字或编号；承载状态记录在 `video_metadata.json` 和 `connection.json`。视频不是机器人运动学证明。
- `batch_run.log`、`batch_run.json`、`results.json`、`results.md`：本姿态的日志、运行记录和结果索引。总表只打印到终端。

完整设计成功要求：Step3 连续接触载荷覆盖、Step5 实际接地凸包覆盖、同一实体的碰撞与间隙检查、完整轨迹、工件及支撑共享接触反力的连续承载均通过。证据审计通过不等于设计成功。

```sh
python slides/baseline_algo/step3_scheculer/rerun_common_directions.py --from-step 3 --through-step 3 --resume
python slides/baseline_algo/step4_floor_contact/rerun_step4.py
python slides/baseline_algo/step5_connect_support/rerun_belt_assembly.py
```

`--shape-budget` / `--connection-edge-budget` 在当前入口表示方向候选预算，默认 24、上限 24；每个方向的框架外扩和底座构造使用固定有限菜单。没有把只检查过几何的候选当作完整通过。

过时的接触重拟合提案、旧版独立支撑受力与接触比较入口已删除。当前批量流程与诊断入口只读取当前阶段的结果。

## 失败也必须可查看

失败结果会保存到同一个 `output/{object_name}/{pose}/step5_connect_support/`：

- `failure_viewer.html`：离线可打开的交互查看器，可旋转、缩放、切换诊断方向、拖动失败动作。红色区域是实际位移后求得的实体交叠，物体固定、所有支撑构件共同移动。
- `failure.png`：原位材料、被拒绝的退出状态、碰撞放大三联图。
- `failure_directions.png`：各个被拒绝方向与阻挡头的对照图。
- `failure.mp4`、`failure.gif`：失败动作演示，明确标注为失败，不作为成功装入轨迹。上游未完成时仅提供部分几何和静态诊断。
- `failed_shape_mm.stl`：实际尝试材料的原位形状；`failure_pose_mm.stl` 为失败位置的形状；`workpiece_mm.stl` 是同坐标系的物体。全部使用毫米。原位形状另有以米为单位的 `failed_shape.stl`。
- `failure_collision_XX_mm.stl`：相应事件中被独立求出的实际相交体积。
- `failure.json`：方向、位移、碰撞构件、实际相交体积、停止阶段、文件哈希。诊断采样仅用于展示碰撞，从不用于接受一条路径。

早期方向检查失败时，保存和显示实际已经构造的头，并明确标注“框架、底座尚未构造”；不能把不存在的完整支撑画成已经尝试过的形状。后续颈部、框架、底座或连接检查失败时，`failed_attempt.npz` / `failed_attempt.json` 保留构造最远的一次实际尝试，包括被拒绝的构件，不能丢弃后只显示一个失败字符串。

无共同方向时，查看器展示工作面背向、各个头的背向等诊断方向。这些方向本来就被约束拒绝，图中不把它们称为可行方向；它们用来直观显示哪个头会被阻挡。如果某次运行上游未完成，展示最后保存的部分接触，并明确标注阶段未完成。

失败诊断中红色为真实材料相交，橙色为预留间隙包络与物体相交；两者分别记录，不能把间隙不足写成材料穿透。如果整件轨迹已通过但承载或上游覆盖未通过，保留成功轨迹视频并另存静态设计失败诊断，不另造一个碰撞动作冒充失败原因。

实体连通性按材料判断：一个正向外壳可以含多个反向内腔表面。只有一个正向外壳、所有内腔经实体差集确认位于其中，且整体闭合、朝向一致、体积为正时，才认定为一个实体。内腔保留；内腔中的独立实心岛或外侧碎片仍判为多个零件。`boundary_component_count` 与 `component_count` 分别记录边界壳数和材料分量数。
# 承载失败的受力图

整件几何已生成但承载未通过时，绘图入口另存 `bearing_failure.png/json/npz`。它重放最后测试摩擦系数下的首个失败工况，显示实际支撑、重力和作用于支撑的头合力；并在仅要求工件平衡的所有非负反力分配中最大化支撑所需地面法向力。最大值仍为负时，标记为数值上的抬离地面问题。这个放松检查不是新的验收证明，也不模拟真实跌落；连续外包顶点与实际载荷明确区分。

腰带未通过单实体检查时，`connectivity_failure.png/json` 标出实际布尔结果中的额外非负体积边界壳，并提供毫米 STL。边界壳数量不能直接解释为实物断成多少块；尤其存在近零体积退化面时，只报告连通性未验证，并保留全部原始材料。
