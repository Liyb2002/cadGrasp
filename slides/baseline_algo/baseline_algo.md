# 当前 baseline 算法

2026-09-13 根据现行代码和已保存输出核对。本文描述实际执行的算法；本次文档整理没有修改搜索代码或重新运行案例。

算法输入是一个工件的**既定目标姿态**，输出是一件连接所有接触头的刚性支撑及共同直线装入轨迹。它先选择接触，再构造结构，最后验收承载；不是对接触、结构和路径作统一全局优化。

## 输入、约定与目标

输入：完整三角网格、质心 `c`、绿色工作面、原始地面接触点、固定目标姿态。世界坐标为右手 Z-up，地面 `z=0`，重力 `-mg zhat`，长度用 m。保存的力按 `mg` 归一化、力矩按 `mg·m`；求解器另可按物体尺度调节数值条件。文件名带 `_mm` 的 STL 用 mm。

令 `A_obj` 为完整工件表面积、`D` 为包围盒最长边。加工位置 `q`（数据字段 `pt`）在工作面上，力方向在该处内法向 30° 半角锥内，力度从 0 到 `0.5mg`。`r_push=q-c`，一个工况的完整需求是

\[
b(q,F_{\rm push})=(F_D,\tau_D)
=\left(mg\hat z-F_{\rm push},\;-r_{\rm push}\times F_{\rm push}\right).
\]

各工况依次考虑，不能把所有采样力同时加到物体上。接触力可以随工况变化，支撑几何与最终装入方向必须固定。

接触头提供无摩擦单边法向力，无压强上限；不按竖直方向筛选头。所有头属于同一个无自重刚体。Step1 仍检查工件对工具射线的遮挡；`support_policy.ENFORCE_PROCESS_ACCESS=False` 仅表示后续支撑不再避开整个加工射线体积，实际工作面仍须避开。

当前不搜索工件翻转过程，不做跨姿态复用、结构强度、变形、支撑自重或机器人运动学验证。

## Step1：采样六维载荷需求

入口：[needs.py](step1/needs.py)；[阶段说明](step1/README.md)。

1. 按真实工作三角面面积选面，再在面内均匀抽取位置。
2. 在局部 30° 内法向球冠按立体角均匀抽方向，在 `[0,0.5mg]` 均匀抽力度。
3. 用完整工件网格检查工具射线，拒绝被遮挡的载荷并补足数量。
4. 默认保存 **32,768 个**配对载荷与六维需求，种子 `20260907`。所有候选共用这份样本。

零加工力是连续域端点，不额外加入随机表计分；Step3 对纯重力另设硬检查，Step4 也显式加入纯重力行。
覆盖率估计的是“工作面积 × 方向立体角 × 均匀力度，经可达性筛选后”的载荷完成比例，不是纯工作面积比例，也不是六维空间的体积占比。

## Step2：生成接触圆和方向表

入口：[circles.py](step2_local_support/circles.py)、[insertion_directions.py](step2_local_support/insertion_directions.py)；[阶段说明](step2_local_support/README.md)。

- 在非工作面、`z ≥ 1.5 mm` 的曲面上按真实面积分配 **200 个中心**。不连通层和不同主朝向分开分配；使用等面积分格，不用三维聚类或可见性分配配额。
- 每个中心与球形邻域相交，保留包含该中心、沿真实共享边连通的曲面部分。目标为 `1% A_obj`，允许因可用连通面积或几何限制得到较小接触。
- 整块任意两处外法向夹角必须 `≤90°`；超角时缩小同中心半径。按实际曲面面积计算，不用 `πr²` 替代。
- 将接触面构造成深度约 `0.01D` 的真实头实体，检查物体和地面净空。初始头碰撞失败直接淘汰，不自动改中心或重拟合以挽救。
- 建立共享的有限三维退出方向表。先排除向下穿地面的方向及工作面外侧半球，再对每个头检查局部法向约束和实际实体的完整直线扫掠。未决方向不作为通过。

保存的是各头可以沿 `+d` 退出的方向 ID；装入方向相反。此处只有候选头，没有连接框架或底座。

## Step3：最多 3 轮贪心选择与尺寸优化

入口：[scheduler.py](step3_scheculer/scheduler.py)；[阶段说明](step3_scheculer/README.md)。已选头的中心与尺寸在后续轮次固定。每轮执行以下过程。

### 3.1 硬筛选，再计算联合覆盖

排除已选候选、Step2 几何失败候选、初始面积不严格大于 `0.5% A_obj` 的候选，以及会使共同退出方向集合变空的候选。初始候选被排除后，不先尝试缩小/放大再让它重新进入评分。

对“此前固定头 + 当前候选 + 工件原始地面支点”检查纯重力下的共同平衡，失败则不参与排名。通过后逐工况重新求**同一组**反力，使其同时满足

\[
\sum_i f_i=F_D,\qquad
\sum_i(p_i-c)\times f_i=\tau_D,\qquad
f_i\text{ 属于相应的单边接触力锥},
\]
\[
\sum_{i\in\text{头部接触}}f_i\cdot\hat z\geq0.
\]

前三项含工件自身的地面支点，最后一项只加总头部。`f_i` 是支撑对工件的力；最后一项意味着工件对整个支撑的合力不向上拔起它，允许个别头下压工件。它是无自重支撑的整体必要条件，不代替真实底座平衡。

实现仍保留六维外部需求；LP 加一个第七维零目标，以 `sum(头部 Fz)-N=0, N≥0` 表示不上抬约束，不是增加第七种外部载荷。工件原始地面支点用四射线摩擦锥，`|Fx|+|Fy|≤64Fz, Fz≥0`。64 是当前充分摩擦模型参数，不是实测材料系数。

联合覆盖要合并所有反力列后重新求解，不能把各头单独通过的样本集合做并集。实现复用可行反力基和已验证的分离平面来批量分类，其余载荷继续解完整 LP。

### 3.2 选择一个头

按联合覆盖样本数降序，选最大者；并列按候选 ID 排序。不按面积归一化排名，也不尝试所有两头/三头组合。零即时增益允许入选，但不能绕过上述硬条件。

### 3.3 只优化新头的同中心半径

目标为

\[
\mathrm{efficiency}(r)=
\frac{\text{旧头与新头的联合覆盖率}(r)}
{\text{旧头总接触面积}+\text{新头接触面积}(r)}.
\]

半径可缩小或扩大。下界保证面积严格大于 `0.5% A_obj`，并保持纯重力共同平衡；上界由整块几何、物体/地面净空及与旧头共享的退出方向约束。只在效率提高时改变原半径。

尺寸搜索利用覆盖数与面积随嵌套半径的单调性作区间上界细分，不假设效率单峰。默认相对效率间隙目标 0.1%，最多 512 次尺寸评价；耗尽预算或到半径分辨率时保存剩余间隙，不能把局部数值搜索说成全局设计最优。

导出实际三角面后重新验证面积、受力与共同方向。旧头保持不变；尺寸目标可能以减少覆盖换取更高面积效率，所以必须在**优化后**重新判断完成。

### 连续验证与停止规则

优化后所有搜索载荷通过，才进行连续载荷域验证：通过需求外包及有证据的非负反力证明连续覆盖；部分证书覆盖包含遮挡方向的更大载荷域，因此可能保守。不能仅以随机样本 100% 作为完成。

- 连续验证通过：Step3 成功停止。
- 找到真实、可达的失败载荷：加入 `search_loads/`，在剩余轮次继续选头；原始 `samples.json` 不改。扩展表上的比例不再是纯随机估计。
- 连续验证未决：停止为 `continuous_validation_inconclusive`，不当作成功或全局无解。
- 3 个头用完仍未完成：`contact_limit_reached`；没有合格候选：`candidates_exhausted`。
- 优化后的共同方向复核失败：停止并保存失败状态。

算法不回溯换头，不重调以前头的尺寸，不自动加第 4 个头。每轮都必须让当前组合能承受纯重力并且整体不上抬，所以某些必须多个头一起加入才可行的组合会被剪掉。

## Step4：只计算地面需求

入口：[whole_assembly.py](step4_floor_contact/whole_assembly.py)；[阶段说明](step4_floor_contact/README.md)。

读取纯重力、Step1 样本和 Step3 新增反例的完整六维载荷，计算所需地面压力中心。另用工作三角形顶点与方向锥外包多面体构造连续需求保守外包，再映射到地面。

若外力合力为 `W=-mg zhat+F_push`，关于地面原点的合力矩为 `M=c×(-mg zhat)+q×F_push`，则 `N=-Wz>0` 时

\[
p=(M_y/N,\;-M_x/N,\;0).
\]

输出实际载荷落点、连续外包点、完整六维载荷和原始工件支点。外包点不是实际抽到的加工力，不能混称为样本。

本步不选底脚、不造支撑多边形、不决定连接结构；这些均留给 Step5。地面需求与选了哪些头无关，除输入中可能包含 Step3 发现的反例。

## Step5：先方向，后结构，再检查承载

入口：[belt_assembly.py](step5_connect_support/belt_assembly.py) 调用 [direction_first.py](step5_connect_support/direction_first.py)；[阶段说明](step5_connect_support/README.md)。

1. 读取实际优化后头的共同退出方向，按工作面背向偏好排序，最多尝试 24 个方向。保留固定头，不重选、不改接触面。
2. 先检查全部头沿该方向的完整扫掠，再从头内部引出颈部，连接到物体背侧接头和宽松框架。框架可为开放树形，不要求闭合或贴物体。
3. 根据 Step4 的需求点和连续外包构造需求凸包，设计方向相关的开口底座；菜单包含开口圈和较宽的 U 形底座。用实际接地材料加工件原支点检查需求覆盖。
4. 连接框架与底座，布尔合并为一个实体，检查间隙、接触保留、实际接地凸包和整件连续直线退出轨迹。框架/底座主间隙为 `0.02D`，颈部另用较小过渡间隙。
5. **第一套几何与轨迹通过的结构立即结束几何搜索。** 然后对该结构作承载检查：工件与整件支撑分别列六维平衡，共用作用力/反作用力；工件支点和底座都有单边摩擦接触。依次试 `μ=1,4,16,64`，每档先查样本，再查连续外包。

**若四档摩擦下仍未取得连续承载通过，当前代码保留该结构并报告未通过，不继续尝试下一套结构，也不返回 Step3。** 外包验证失败本身不一定给出实际可达工况的反例，有限方向/形状/摩擦菜单失败也不证明全局无解。

方向表是三维的，可包含水平或向上的退出方向；仅搜索直线平移，不搜索旋转或折线路径。实际完整实体必须通过连续扫掠，不能用若干视频帧代替验证。

## 什么算完成

`connection.json` 的 `passed=true` 要求 Step3 连续覆盖、Step5 几何与实际接地检查、整件连续轨迹、共享反力的连续承载同时通过。

`complete=true` 仅表示流程结束；`audit.json` 的 `passed=true` 表示证据审计通过，失败设计也可以通过审计。视频只说明有已验证的运动轨迹，不能单独证明承载。模型内设计通过也不表示已经验证实物打印强度。

即使 Step3 已完成但未成功，Step4/5 仍可构造部分几何并保存诊断；不能把它们的存在当成完整成功。

## 运行

在仓库根目录、安装了本项目依赖的 Python 环境中执行：

```sh
# 只完整重跑 B 的两个姿态
python slides/baseline_algo/step3_scheculer/rerun_common_directions.py \
  --from-step 1 --workers 2 --case B:pose_1 --case B:pose_2

# 单个姿态，从指定阶段继续
python slides/baseline_algo/step3_scheculer/run_all.py B --pose pose_2 --from-step 4

# 只更新 Step3 最终接触块与共同方向图
python slides/baseline_algo/step3_scheculer/draw_result.py B --pose pose_2

# 重放换轴前后 B 设计的独立对照（参考数据本身也使用 Z-up）
python slides/baseline_algo/step5_connect_support/check_coordinate_equivalence.py

# 各目录的独立回归检查
python slides/baseline_algo/step3_scheculer/check_tests.py
```

批量入口的 `--resume` 会先检查来源和审计，再复用有效检查点。不指定 `--case` 时运行 A1-f、B、C5 的全部四个姿态。旧参数名 `--connection-edge-budget` 在当前 Step5 表示方向候选数，上限 24；每个方向试固定的框架外扩和底座菜单。不同姿态可以并行，同一刚体的连接搜索串行进行。

入口退出码 0 表示模型通过，2 表示流程完成但设计未全部通过，其他非零表示执行或审计错误。

## 计时与候选并行（2026-09-13）

总入口在最后请求阶段保存 `timing.json`，逐条记录阶段子进程的实际墙钟时间、退出码和 Step1–5 合计，包含进程启动、读写、审计及默认绘图。Step3 的 `schedule.json` 另有 `wall_timings`，记录 3.1、3.2、3.3、连续验证及尺寸优化/方向更新/绘图子项；3.3 总时间包含这些子项，不能重复相加。3.1 新计时包含并行评分预计算，旧 `scoring_seconds` 保留其历史口径。

相同输入可能直接命中 Step2 方向缓存，即使没有 `--resume`。测量从头计算的耗时时使用 `--force-directions`；测量生产中的缓存运行则省略它。计时记录从获取姿态锁后开始；被跳过的阶段不会冒充重新计算，多物体同一命令的时间也不能按物体重复求和。

```sh
# 单姿态：4 个方向检查进程，3 个评分进程，强制重算用于性能对照
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
CADGRASP_DIRECTION_WORKERS=4 CADGRASP_SCORE_WORKERS=3 \
python slides/baseline_algo/step3_scheculer/run_all.py B --pose pose_1 \
  --from-step 1 --continuous-retry --connection-edge-budget 24 \
  --force-directions --timing-name timing_after.json

# 不改基线结果：抽取 20 个合格头，比较串行/4 进程与已保存的方向证据
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
python slides/baseline_algo/step2_local_support/benchmark_directions.py A1-f \
  --pose pose_1 --count 20 --workers 1 4
```

Step2 单独入口也支持 `insertion_directions.py B --force --workers 4`。未指定时采用 `CADGRASP_DIRECTION_WORKERS`，缺省仍为 1；批量案例并发和候选进程数相乘，需按可用 CPU 调整。几何判据、候选/方向顺序及返回证据不变，工作进程不写输出。进度改为每 10 个候选或 10 秒原子保存一次，并在完成或异常时刷新；强制杀进程可能丢失最近一段未保存工作，续跑会重算该段。

代码指纹变化后历史证书需要重新计算或审计，性能测试的证据比较不替代完整案例验收。性能记录和回归日志仍保存在相应姿态的阶段目录内。

换轴前的性能对照：B/pose_1 从头执行 Step1–5 的总时间为 245.5 → 150.3 秒（降低 38.8%），其中退出方向检查为 131.5 → 36.5 秒。全部 200 个候选的方向记录、最终接触与支撑几何数组一致，完整设计验证通过；相关回归共 123 项通过。旧的逐次计时产物已清理，上述数值只保留为历史性能记录。每种配置完整测量一次，不将其他阶段的小幅波动当作加速效果。

A1-f/pose_1 另取 20 个合格候选做纯方向检查：单进程 105.1 秒，4 进程 75.8 秒，所有证据记录一致（旧的子集计时产物已清理）。这不包含圆拟合、方向表构建、检查点和后续阶段，不能当作 A1-f 的完整运行时间或全流程加速比。这些是换轴前的性能测量；本次 Z-up 重跑的时间见各姿态 Step5 的 timing.json。

## 输出、来源与清理约定

所有案例输出位于 `output/<物体>/pose_<编号>/<阶段目录>/`。保留既有名称，包括 `step_1_needs` 和 `step3_scheculer`。运行脚本放所属阶段；不新增根层运行、归档或独立汇总目录。规则见 [AGENTS.md](../AGENTS.md)。

- Step1：`needs.json`、`samples.json`。
- Step2：候选圆及实体数据、`insertion_directions.json`。
- Step3：逐轮候选过滤、贡献表、选择、尺寸记录；最终 `schedule.json`、`final_contacts.npz`、共同方向和连续证书。
- Step4：`floor_contact.json/npz`，含需求点与连续外包。
- Step5：`connection.json`、`audit.json`、`geometry.npz`、`support.stl` / `support_mm.stl`、`trajectory.json`、`bearing.npz` 及图片/视频。失败也保留当前实际尝试和原因。

不要因算法未成功删除其失败证据，也不要将旧坐标迁移或图像更新记录当成本次重新搜索。当前 B 的换轴对照由 `coordinate_equivalence.json` 和 `coordinate_reference.npz` 保存；坐标迁移不改变既定姿态。

代码或输入改变后按来源哈希重算/审计；仅修改本文不构成新实验。此前旧入口和过时输出的清理已完成，本轮文档整理不再次删除 baseline 数据。
