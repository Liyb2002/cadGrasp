## 代码在哪里改变了问题

1. `run_greedy.read_case` 复用了共享头的源形状，但仍为两个任务各保留一份头列表。
2. `run_greedy.placements` 为这两份列表选择独立的旋转和平移，没有要求共享面的对应点在支架坐标中重合。
3. `greedy_geometry.Constructor.__init__` 遍历每个 pose 的每个头，均新增一个 `Head` 和身体。因此 `pose_1_C041` 等共享编号变成两份实体。
4. 验收检查的是每个 pose 自己那三个头的接触、六面实体的几何和受力，没有检查跨 pose 的物理头身份。反力重放通过不能补足这个遗漏。

## 新版比旧版差在哪里

旧版也有共享头分裂，外形被认可不能说明原五头定义成立，直接恢复归档仍未修复这一点。

在此之外，新版又改变了支架摆放搜索：旧 1+3 使用倾斜地面之间的紧凑摆放；新版采用相向平行地面的候选，并允许较大横向错开，1+3 最终横向偏移约 184.4 mm。旧构造先让各头身体向另一姿态地面延伸，新构造只从短头背部开始，再逐点选择最近的头。结果很容易各自服务自己的地面，最后才用长桥连起来。最小生成树只优化既定候选桥的长度，不会重新注册共享头，也不会恢复局部跨姿态复用。

1+3 体积从 141.426 增至 176.573 cm³（约 +24.9%），最大外形尺寸从约 198 增至 378 mm。2+8 的八个显式接地端全部分给同 pose 的头。这些结果说明当前构造没有保住之前希望得到的局部复用方向。

## 修正顺序与当前输入的限制

先按唯一 ID 建立五个物理头，将完整共享面的对应关系注册到同一支架坐标。两姿态变换必须满足这一注册，不能再独立移动两组三头。之后才在共同允许空间里选择落脚点、长身体和连接；不限定每个地面必须有几个头提供脚面。

但不能承诺把两个橙色面强行合并就能修好。对**现有完整共享面及其原始物体材料点对应关系**，相对变换由原任务坐标关系确定。任一地面的合法落点都必须位于另一地面的上半空间；原物体支点也须纳入。所有地面法向力非负时，合成压力中心也只能在这个半平面内。地面切向摩擦不能改变这一关于水平轴力矩的必要条件。

在这个严格注册下，仅用原 32,768 个载荷得到：

| 配对 | 第一 pose 越过另一地面允许半平面的需求数 | 第二 pose 越界需求数 |
|---|---:|---:|
| 1+3 | 1713 | 0 |
| 1+4 | 356 | 4 |
| 1+6 | 0 | 77 |
| 2+8 | 2257 | 0 |
| 6+9 | 0 | 32510 |

因此这些固定任务、固定完整接触对应关系下，单靠添加身体不能满足全部原地面需求。该结论不涵盖改变接触对应关系、允许滑移或重新设计共享接触的情况；这些都需要显式重建接触与受力验证。不能通过复制共享头绕过失败，也不能把构造算法失败归咎于最近邻或 MST 本身。
