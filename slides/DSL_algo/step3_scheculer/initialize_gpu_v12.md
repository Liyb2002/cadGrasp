# Independent initialization with wider greedy sampling

Run `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=slides/DSL_algo .venv/bin/python -m step3_scheculer.run_initialize_saved_v13` from the repository root. The search engine is immutable V12; V13 reads frozen, byte-identical original inputs after the global object dataset changed during the experiment.

Each saved B pose is solved independently. No other pose supplies forces, excludes contacts, or sets a common exit direction. Immutable independent Step1 snapshots and all 32,768 original loads are reused.

Search permits up to six heads and provides thirty trajectory slots, ten each for fixed per-head surface areas of 1%, 2%, and 0.5%. Each family stops after its first successful trajectory. At every step, rank geometrically eligible additions by actual newly covered loads and sample among the top ten, with probability proportional to coverage gain; if all gains vanish, sample uniformly. A trajectory only adds heads. No replacements, parameter descent, adaptive load collection, or force subsampling are performed. Even one head may terminate if every constraint passes; three heads are not a physical requirement.

The exit menu preserves the horizontal directions and adds oblique and vertical directions. Direction vectors describe virtual head movement; actual object withdrawal is the opposite vector. The object may not move through the ground. Continuous individual head sweeps, a common exit, and a shared checked geometric roadmap component are required. These are local head checks, not a constructed full support witness. Full Step4 construction is a separate stage.

CUDA float64 evaluates reusable primal/dual LP certificates for the full load batch. CPU solves the original LP and performs surface clipping, area fitting and continuous geometric checks. GPU uses conservative certificate margins and the unchanged CPU classifier independently checks the selected final design. GPU speed is not an assumption; timings include actual search and candidate construction where recorded.

Outputs are isolated in `slides/DSL_algo/output/B/independent_poses_gpu_v12/`. Old independent and current multi-pose DSL results are preserved. Each pose contains actual final contacts, candidate families, sampled trajectories with top10 probabilities, full coverage masks, local exit evidence, provenance and a head visualization. Search failure does not establish physical infeasibility.

The global `objects/B/tasks` snapshots were replaced during the batch by a different thirty-pose dataset in `objects/B/poses`. These are not the old twenty poses. `recover_initialize_inputs_v13.py` reproduces each original setup archive from retained immutable domains and the original construction formula, and accepts it only when its complete file SHA256 matches the original stored hash. All twenty matched exactly. Frozen domains, loads and setup snapshots are stored under each new pose’s `input/`. Already completed reports receive a recorded identical-byte input-path migration; interrupted exported winners are checked and finalized by the V13 adapter. Historical/current multi-pose outputs are not altered.
