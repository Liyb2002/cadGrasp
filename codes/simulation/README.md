# 无文字的双 LBR Med 流程视频

另有复用本目录 KUKA 模型、逆运动学和位姿工具的 [共享底座多接口概念流程](../../slides/belt_test/code/shared_workflow.md)，新代码及输出均位于 `slides/belt_test/`。该分支展示一次接触模块安装和三个 task 的底座对接，采用无右侧步骤的全幅单臂运动学视频，并在该分支内替换为共同掌座、两个滑动指爪的夹爪；下面的无文字、双臂与唯一输出约定仅描述本目录原有 `run.py` 入口。

2026-09-18 任务约定更新：机器人使用 KUKA LBR Med；准备阶段允许抓取、抬起和重新放置，工件质量按实验机器人与工具的能力选择，见 [当前问题定义](../../slides/README.md#要解决的问题)。优先采用通用夹爪与预设搬运路径，按搬运可行性选择目标姿态。以下描述现存视频及代码：其中的贴地推扶仍是旧演示的运动学编排，没有验证推力能驱动物体沿该路径扶起，也尚未改成 KUKA 抓取摆放流程。

后续多状态仿真须连续执行同一工件与共享支撑的安装、释放、机器人重新接管、换姿态和再次落座，并在各工作姿态下独立测试持续载荷。允许移动工件或支撑完成相对安装，具体检查机器人、夹爪、地面和整件实体的路径。运动规划可用已有方法；执行阶段须由机器人驱动及明确的接触/连接模型产生运动，不能逐帧指定工件和支撑位姿来证明动作可行。腰带是否随工件运动及如何保持尚待明确；当前无摩擦单边接触不能直接替代刚性连接。

现有 `Presentation.frame` 逐帧写入物体、支撑和机器人位姿，清零速度后调用 `mj_forward`，未进行时间积分。现存单姿态视频因此不构成上述多状态操作过程的物理验证，原有末尾静力检查仍只认证工作姿态下的平衡。

从仓库根目录运行（使用已安装 `requirements.txt` 依赖的 Python）：

```sh
python codes/simulation/run.py --overwrite
```

唯一输出为 `simulation/videos/B_pose2_full_workflow.mp4`，默认 71 秒、30 fps。
视频不显示标题、字幕、编号、数值、状态条或机器人标签；载荷只用持续的箭头表示。
不生成网页、报告、图片、轨迹、模型或代码快照。模型和验证结果留在内存中，
MP4 在系统临时目录编码完成后替换输出文件。

## 机器人与动作

两臂均使用 [LBR-Stack 的 KUKA LBR Med 14 R820 模型](https://github.com/lbr-stack/lbr_med14_r820_description)，
真实尺寸、原始网格、七轴链和关节限位均来自固定版本；模型上的品牌字样在渲染时改成环带底色。来源和许可证在 `assets/lbr_med14_r820/`。
A 的末端为开放式推扶掌板，不包夹物体；B 的末端用于夹持 fixture。
运动由受关节限位约束的逆运动学求解，并检查关节速度及机器人网格不穿地。
这是运动学过程回放，尚不是经过抓持力、执行器力矩与全场景碰撞验证的真实机器人控制方案。

物体从真实几何求出的稳定躺姿开始。扶起使用凸包支撑顶点的分段支点翻转：
每段当前接触点固定在地面，解析检查整段圆弧中所有顶点都不穿地，且始终有接触点在 z=0。
路径最终精确回到保存的 target pose；不存在离地抬升或在空中改变姿态的阶段。
到达 target pose 后才显示绿色工作面。

A 保持推扶，B 沿 Step6 路径推进 fixture。生成前重新回放验证夹具整件扫掠。
B 先松开撤离，A 再撤离，之后检查无机械臂反力的重力平衡。

## 十个随机载荷

固定种子 `20260920` 从工作区域与允许的载荷域抽取 10 个独立载荷。
每个力持续 4 秒，最后一个在结尾额外保持 2 秒。每个案例内的世界坐标作用点、
力的方向和大小不变，箭头持续显示；相邻案例替换载荷，不叠加。
`--seed` 更换随机载荷；`--test-seconds` 修改每个力的展示时长。

载荷部分沿用无惯性静力验证：检查接触几何，联合求解两个自由物体的力与力矩平衡，
再独立核验反力与加速度。机器人不进入这些平衡方程；平衡未解决时停止生成。
视频不作动力学稳定性结论。

`shape/` 是固定物体和支架输入。检查命令：

```sh
python -B -m unittest discover -s codes/simulation -p 'test_*.py'
```
