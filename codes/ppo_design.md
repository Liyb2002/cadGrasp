## 1. 核心选择

训练一个根据当前设计和任务条件决定下一步几何编辑的策略。一个 episode 是数字设计过程，不是把未完成的支撑逐件安装到物体上的物理过程。

PPO 是策略训练器。几何构造、接触求解与连续验证继续由确定的环境实现。网络输出设计动作，不负责给出最终可行性证书，也不直接输出每个加工载荷下的接触反力。

将“改变几何表达”和“学习搜索策略”分开实验：第一版复用现有接触区域和结构构造能力，建立同动作空间的多采样对照；随后再增加更自由的区域/骨架编辑。第一版结果只能说明在该表示下的学习效果。

## 2. 单姿态状态

任务输入为 O（工件）、T（目标姿态）、W（工作区域）、L（加工载荷域）及接触模型。数据结构从开始就支持任务列表，单姿态是列表长度为 1。

几何用工件局部坐标保存，姿态 T 将其变换到世界坐标。接触保留源面 ID、局部位置、法向和实际区域边界。地面、重力、工作面和载荷的相对关系必须显式输入，不能只输入一个 pose 编号。

动态状态包括：

- 当前头部区域及尺寸、底座参数、连接构造参数和退出方向。
- 生成的真实几何或尚未生成的明确状态；不可用的数据有独立标志，不能用零残差冒充已通过。
- 每个阶段的评价状态：未检查、样本通过、连续通过、实际反例失败、保守外包未通过、求解未决、几何失败。
- 代表载荷的归一化平衡残差/覆盖信息、当前共同方向信息。
- 上次构造失败阶段、已使用评价预算、剩余编辑步数。

可用图网络编码曲面候选及当前设计图，用任务编码器输入姿态/地面/重力/工作面/载荷。第一版不要求完整网格端到端进入大网络，采用候选局部几何和力旋量特征即可；不要只用平均法向和面积代替区域信息。

静态网格预处理结果可以缓存；训练中的网络特征若依赖正在更新的权重，需要随更新重算，不能永久缓存成过期 embedding。

## 3. 第一版动作

使用按“动作类型 → 目标对象 → 参数选项”分解的条件分类策略。先用离散参数菜单，避免第一版同时处理连续动作投影和 PPO 概率密度修正。记录完整条件动作概率与 mask。

| 动作 | 第一版行为 |
|---|---|
| 增加头 | 选择候选中心和一个经几何生成的尺寸档 |
| 替换/删除头 | 修改已有选择，而非永远冻结旧头 |
| 调整头尺寸 | 对任意已选头选择相邻尺寸档，重新生成并检查几何 |
| 选择方向 | 选择所有当前头兼容的离散退出方向 |
| 选择底座/结构参数 | 显式选择现有底座种类、外扩和框架参数选项 |
| 构造并评价 | 对指定参数构造完整结构，得到当前验证器的结果 |
| 提交 | 请求终局验证；只有完整验收通过才算成功 |

不把整套隐藏贪心搜索悄悄放进一个动作再称为 PPO 的功劳。若复用自动连接器，应公开它能搜索的范围、确定性规则、实际评价次数，所有对照共用。

初始先保留现有最多 3 个接触区域作为预算与对照条件；允许更多头、区域生长和连续方向是后续独立变体。目录中的候选数不应成为网络输出固定维度，策略应对候选集合评分。

“接触组/底座/方向改变”会使依赖它们的结构和证书失效；环境必须显式清除有效标志，不能将旧完整通过奖励带到新几何上。

对确定无效的参数、重复添加、越界、工作面接触等操作做 mask。对于尚可被后续编辑修复的失败，不凭预测低分永久 mask。

## 4. 中间设计与 baseline 的差异

建议新 PPO 环境允许数字草稿暂时未承载或未连接，否则不能探索互补接触。最终提交仍要求纯重力、不上抬、共同反力、几何和连续轨迹等全部条件。

这会改变 baseline 每轮纯重力筛选、旧头固定和承载失败停止的搜索规则，必须作为新算法明确记录。若先做严格同规则对照，可保留“可行前缀”模式；不能把其限制下的失败解释为 PPO 无法学习全部设计。

允许编辑前缀不代表实际装配途中无人保持工件；当前仍采用安装时由外部保持目标姿态的模型。基线文件与其验证语义不应被原地改写；新环境调用力学/几何内核，并单独定义终局验收，而非伪造 baseline 调度证书。

## 5. 评价与奖励

每步评价只针对受影响的部分；共享承载方程是现有方法，不重新发明一套。提交时使用完整连续验收。当前几何误差或求解未决都不能被标为物理不可行的证明，也不能算成功。

以“完整通过”为首要终局目标。可用一个明确有界的原型：成功回报 1−0.1C，未成功为 0，C∈[0,1] 是可行设计成本；费用归一化与权重固定在实验配置中。C 可先只使用接触面积，材料体积随后单独比较。这里的数值是拟用初值，不是调参结果。

采用有限编辑时域，原型可用 32 步，作为待测超参数。为保持终局目标清楚，先用 γ=1。中间添加有界势函数差 Φ(s_next)−Φ(s)，终态 Φ=0；完整轨迹中势函数差望远镜求和，避免反复扩大/缩小同一设计刷奖励。不同终止原因都必须正确处理终态值。

势函数可从固定代表载荷的覆盖和归一化残差构造；求解目标使用力 mg、力矩 mgD 的尺度。样本通过只是训练信号，不替代连续验证。开始不增加许多未校准的碰撞、方向、杆长奖励项。

动作预算和验证预算显式进入状态。耗尽有限设计预算作为该任务定义的终止；rollout 数据采集截断则需要 bootstrap，两者不能混淆。

第一次出现通过设计可保存为 incumbent。如果未来允许成功后继续减材料，应将 incumbent 纳入状态，并明确奖励是提交当前设计还是提交最好已认证设计，不能隐式混用。

## 6. PPO 网络与训练

- 一个共享编码器，actor 按类型/目标/选项输出条件动作，critic 预测剩余设计回报。
- 先用同一动作空间的随机多采样跑通环境；它是正式对照，也用于暴露无效动作和奖励漏洞。
- 已认证设计及其扰动可用于修复任务、行为克隆预热；这些只是辅助初始化，旧日志不能直接充当标准 on-policy PPO 轨迹。
- PPO 训练使用当前策略新采集的轨迹。分离探索编辑时的便宜评价和提交时的完整验证，统计所有嵌套计算成本。
- 从容易任务/较少工作面载荷开始的课程只用于训练；最终成绩必须在原目标载荷域下评定。
- 先验证能在现有对象上学会设计，再扩大对象库并按对象划分训练/验证/测试。12 个姿态只来自 3 个对象，不能据此声称跨物体泛化。
- 比较相同预算下的完整通过率、首次成功评价数/时间、可行设计成本；训练总开销单独报告。PPO 的随机种子也需要重复实验。

## 7. 未来共享腰带：变量拆分

2026-09-18 范围更新：以下 H/U_k 的共享腰带与姿态专用模块拆分已作为后续研究方向记录，不等同于同一件完整落地支撑复用；本版暂不实施。未来完整实验与 MuJoCo 需要验证实际姿态转换，详见 [当前问题定义](../slides/README.md#要解决的问题)。腰带是否始终留在工件上、其保持机制和具体模块装卸方式仍需明确。

以下暂按“腰带持续留在工件上，换姿态时只换底座与连接模块”理解；这是待用户澄清的未来方案，不是已经确认的机械约束。

共享设计 H 包括头部区域、将头部保持为一套的腰带实体及模块对接接口。姿态专用设计 U_k 包括底座、连接、与 H 的配合接口及其退出方向 d_k。H 在工件局部坐标中只保存一份；所有任务使用同一份几何。

\[
\exists H,\quad \forall k\in\{1,\ldots,K\},\quad
\exists(U_k,d_k),\quad \forall\ell\in\mathcal L_k,
\quad \exists\lambda_{k\ell}:\ \mathrm{Feasible}(H,U_k,d_k;T_k,W_k,\ell).
\]

H 和 U_k 均不能随加工载荷改变；反力可以。每个任务可以有不同 U_k 和 d_k，不要求全部姿态共用一个世界坐标退出方向。各任务可以主要使用不同的头，但没有使用的头和腰带材料仍实际存在，不能从碰撞检查中删除。

这区别于“同一个 PPO 分别给每个姿态设计一套不同的头”。共享策略权重不保证共享硬件；共享必须是环境中的变量约束。

## 8. 多姿态训练组织

一个 episode 包含同一工件的一组任务 C={(T_k,W_k,L_k)}：编辑共享 H，为每个任务编辑 U_k，汇总所有任务结果。修改 H 后，所有受影响的 U_k 评价和证书失效。

可以仍用一个 PPO actor：共享编辑动作读取全部任务集合，姿态专用动作读取当前任务及共享 H。critic 读取整体状态。设计上分为共享与专用两层，不必第一天就训练两个会互相改变环境的 PPO。

网络对任务集合使用不依赖列表顺序的编码，并保留每个任务的状态、最差任务信号和工作面掩码。只取平均值可能掩盖一个始终失败的姿态。

终局成功定义为所有指定任务均通过。训练势函数可以结合已通过任务比例和最差任务缺口，但最终不能用高平均覆盖代替全部任务通过。共享材料计一次，专用材料成本按任务求和/平均，并由真实使用需求确定成本目标。

若任务很多，可训练时抽子集并加强困难任务；最终必须对完整指定集合验证。子集训练成功不意味着完整集合可行。

## 9. 腰带方案新增的物理问题

1. **装入对象改变。** 腰带留在工件上时，仅 U_k 移动，障碍包括工件和已安装 H；要检查 U_k 整个扫掠以及对接终点。原来“全部头随整件支撑一起退出”的条件不再是每次换模块的条件。腰带自身首次安装需另行定义。
2. **常驻材料避让全部工作面。** 对工件局部坐标中的 W_k，常驻腰带接触至少要避开其并集；整个腰带实体在每个任务下也不能遮挡实际加工区域。当前不自动开启加工射线体积禁区，将来如果要求工具净空需明确另加。若并集过大，固定腰带可能无可行放置，这不是 PPO 能消除的物理冲突。
3. **绑住与单边接触不同。** 当前头只有无摩擦压力，不能直接假定它们提供拉力、粘接或稳定预紧。腰带在换模块期间如何保持相对工件的位置，需有实际安装/保持机制；暂未定义时不能认证这一阶段。
4. **腰带—模块接口。** “接触上了”不等于刚性锁定。若采用理想刚性锁定，装配后可暂将 H∪U_k 视为一个支撑刚体，但这是显式模型假设，且不认证实际接头强度。若靠单边接触/摩擦配合，则须对腰带与模块分别平衡并共享接口反力，不能直接套用原 12 行矩阵。
5. **原有地面接触可能变化。** 腰带在某姿态下可能成为最低点、碰地或改变工件原支点。必须检查实际接地并更新接触集合，不能照搬原姿态的支点。

本草案尚未实现工件翻转、模块拆换或机器人执行的验证。按最新实验范围，所选方案实际需要的转换过程须补充接触、抓持与机器人执行模型，并验证连续执行；不能由静态终点通过推出。

## 10. 实施顺序与资料

顺序建议：单姿态 PPO 编辑环境 → 多姿态任务输入与单姿态泛化 → 给定共享腰带设计各姿态模块 → 联合优化一份腰带和全部模块。后两步依赖腰带保持、对接与初次安装模型的明确，不提前实现。

目前只在数据结构中预留：工件局部坐标、任务列表、共享/任务专用几何归属、接口标识、装配阶段与移动实体集合。单姿态当前整件支撑仍一起装入，这些字段不代表已经实现可拆接口。

方法依据：

- [Schulman et al., PPO, 2017，§3、§5](https://arxiv.org/pdf/1707.06347)：策略概率比裁剪与 actor-critic 训练，不提供几何或物理保证。
- [Schaul et al., Universal Value Function Approximators, ICML 2015，§3](https://proceedings.mlr.press/v37/schaul15.pdf)：价值函数可同时以状态与目标为条件。本文借鉴任务条件输入；共享实体的强制约束是本项目设计，不是该论文的结论。
- [SmartFixture 的作者论文第 4 章](https://vtechworks.lib.vt.edu/server/api/core/bitstreams/1e5b311c-daf9-4ed0-b50b-2da12068f524/content)：图状态、受约束动作和 PPO 用于夹具布局；不支持直接声称多姿态腰带已被验证。
